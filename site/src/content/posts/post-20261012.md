我当年在上数据结构的课程的时候，我们老师讲两个有序链表的归并，用的是以下的例子：

原题干：

![image](./images/post-20261012/mv41pe4u-image.png)

题解：

```c++
// 算法 2.2 / 例 2-3：归并有序表 La 和 Lb 到 Lc
void MergeList(List La, List Lb, List &Lc) {
    InitList(Lc);                     // 构造空的线性表 Lc
    int i = 1, j = 1, k = 0;
    int La_len = ListLength(La);
    int Lb_len = ListLength(Lb);
    ElemType ai, bj;

    // 当两表均未遍历完时，挑较小者插入到 Lc
    while ((i <= La_len) && (j <= Lb_len)) {
        GetElem(La, i, ai);
        GetElem(Lb, j, bj);
        if (ai <= bj) {
            ListInsert(Lc, ++k, ai);
            ++i;
        } else {
            ListInsert(Lc, ++k, bj);
            ++j;
        }
    }

    // 插入 La 表中剩余元素
    while (i <= La_len) {
        GetElem(La, i++, ai);
        ListInsert(Lc, ++k, ai);
    }

    // 插入 Lb 表中剩余元素
    while (j <= Lb_len) {
        GetElem(Lb, j++, bj);
        ListInsert(Lc, ++k, bj);
    }
}
```

这是一个典型的迭代算法，这是显然的，它没有调用函数自身，而是用了3个`while`循环和两个遍历游标来不断的循环迭代，直到两个表的所有元素都被处理完毕。

正巧，我在之前上过CS61B[^1]的数据结构，我记得当时教授讲述归并排序（`Merge Sort`）的时候，也使用了类似的三个`while`循环的结构，于是当时我就瞬间联想到了这一点。

于是进一步的，我自然而然会想到：这两个玩意的名字这么像，他们所使用的方法是一样的吗？都是迭代法？

好吧，不太对，我当时听课的时候教授明确是用递归的思想讲解了归并排序——但是它们的结构也太像了，名字也是一类。

## 也就是说，是迭代赢了

还是来看看当时的`Merge Sort`的`java`原代码：

```java
public static void sort(int[] arr) {
    if (arr == null || arr.length <= 1) {
        return;
    }
    // 为了避免在递归中频繁开辟空间，通常创建一个辅助数组
    int[] temp = new int[arr.length];
    sort(arr, 0, arr.length - 1, temp);
}

// 递归排序函数
private static void sort(int[] arr, int left, int right, int[] temp) {
    if (left < right) {
        int mid = left + (right - left) / 2;

        // 1. Split & Recurse: 递归排序左边和右边
        sort(arr, left, mid, temp);
        sort(arr, mid + 1, right, temp);

        // 2. Merge: 合并两个有序子数组
        merge(arr, left, mid, right, temp);
    }
}

// 核心合并操作 (对应图片 1)
private static void merge(int[] arr, int left, int mid, int right, int[] temp) {
    int i = left;       // 左序列指针
    int j = mid + 1;    // 右序列指针
    int t = 0;          // 临时数组指针

    // 比较并将较小元素放入 temp
    while (i <= mid && j <= right) {
        if (arr[i] <= arr[j]) {
            temp[t++] = arr[i++];
        } else {
            temp[t++] = arr[j++];
        }
    }

    // 将左边剩余元素填充进 temp
    while (i <= mid) {
        temp[t++] = arr[i++];
    }

    // 将右边剩余元素填充进 temp
    while (j <= right) {
        temp[t++] = arr[j++];
    }

    // 将 temp 中的元素拷贝回原数组
    t = 0;
    while (left <= right) {
        arr[left++] = temp[t++];
    }
}

public static void main(String[] args) {
    int[] arr = {11, 10, 6, 3, 2, 8, 7, 5, 4};
    sort(arr);
    // 输出结果应为有序数组
    for(int num : arr) {
        System.out.print(num + " ");
    }
}
```

很明显的自顶向下的递归结构，`sort`函数直接调用了自身，一路把大数组拆成 2 半，再拆成 4 块……一直拆到单个元素（`left == right`递归边界返回）：

```java
private static void sort(int[] arr, int left, int right, int[] temp) {
    if (left < right) {
        int mid = left + (right - left) / 2;

        // 函数在内部调用了自己！这是典型的分治与递归
        sort(arr, left, mid, temp);      // 递归排左边
        sort(arr, mid + 1, right, temp);  // 递归排右边

        merge(arr, left, mid, right, temp);
    }
}
```

但是我们能说这就是一个纯递归的算法吗，那肯定不对，我们都还没看`merge`函数呢，它的内部有这样的结构：

```java
private static void merge(...) {
    // 这里全部使用的是 while 循环和双指针自增
    while (i <= mid && j <= right) { ... }
    while (i <= mid) { ... }
    while (j <= right) { ... }
    while (left <= right) { ... }
}
```

这里的结构不就和题解里面的示例代码一摸一样了吗，没错，这就是一个标准的迭代，**合并这一步本身是用迭代实现的。**

而如果我们纯用迭代来实现归并排序，那么思路大概会是这样的：

直接用双重 for 循环：

- 第一轮把相邻大小为 1 的子数组两两合并成大小为 2 的；
- 第二轮把大小为 2 的合并成大小为 4 的；
- 步长不断翻倍（`step *= 2`），直到覆盖整个数组。

于是有：

```java
// 纯迭代实现的归并排序（完全没有递归）
public static void sortIterative(int[] arr) {
    int n = arr.length;
    int[] temp = new int[n];

    // step 表示当前要合并的子数组长度：1, 2, 4, 8...
    for (int step = 1; step < n; step *= 2) {
        // 步长为 2 * step 迭代遍历整个数组进行成对合并
        for (int left = 0; left < n - step; left += 2 * step) {
            int mid = left + step - 1;
            int right = Math.min(left + 2 * step - 1, n - 1);
            merge(arr, left, mid, right, temp); // 用的还是那个迭代版的 merge
        }
    }
}
```

而且我们可以看出：纯迭代法的时间复杂度依然是标准的 `O(nlogn)`，因为外层循环的执行次数是$\log_2 n$次，内层循环n次。

$$\text{总时间} = \text{外层轮数} \times \text{每轮总耗时} = \log_2 n \times O(n) = O(n \log n)$$

而且事实上**在实际运行耗时（常数项）上，纯迭代版通常比递归版略微更快一点。**

我靠，目前为止在两道题目上怎么看都是迭代法更胜一筹啊，递归法不仅直观想象异常困难，在空间复杂度上也比不上迭代法

那难道说，我们之后在实现有序链表/无序链表归并（无序的话就是归并排序了）的时候就直接无脑迭代法就好了吗？

## 力扣题目中的实现
[21. 合并两个有序链表](https://leetcode.cn/problems/merge-two-sorted-lists/)

这边由于力扣官方没有写C语言的本题实现，我补一版：

迭代法的题解：

:::tabs

```c
ListNode* mergeTwoLists(ListNode* l1, ListNode* l2) {
    // 创建一个栈上的哨兵节点（哑节点），简化头节点处理
    ListNode dummy;
    dummy.next = NULL;
    
    // tail 始终指向当前合并后链表的末尾
    ListNode* tail = &dummy;

    // 当两个链表均非空时，将较小节点接入 tail 后面
    while (l1 != NULL && l2 != NULL) {
        if (l1->val <= l2->val) {
            tail->next = l1;
            l1 = l1->next;     // l1 指针后移
        } else {
            tail->next = l2;
            l2 = l2->next;     // l2 指针后移
        }
        tail = tail->next;     // tail 指针后移
    }
  
    //未处理完的剩余部分，直接整条连到 tail 后面即可，时间复杂度 O(1)
    if (l1 != NULL) {
        tail->next = l1;
    } else {
        tail->next = l2;
    }

    // 真正的头节点是哨兵节点的下一个节点
    return dummy.next;
}
```

```java
class Solution {
    public ListNode mergeTwoLists(ListNode l1, ListNode l2) {
        ListNode prehead = new ListNode(-1);

        ListNode prev = prehead;
        while (l1 != null && l2 != null) {
            if (l1.val <= l2.val) {
                prev.next = l1;
                l1 = l1.next;
            } else {
                prev.next = l2;
                l2 = l2.next;
            }
            prev = prev.next;
        }

        // 合并后 l1 和 l2 最多只有一个还未被合并完，我们直接将链表末尾指向未合并完的链表即可
        prev.next = l1 == null ? l2 : l1;

        return prehead.next;
    }
}
```

递归法的题解：

```c
ListNode* mergeTwoListsRecursive(ListNode* l1, ListNode* l2) {
    if (l1 == NULL) return l2;
    if (l2 == NULL) return l1;

    if (l1->val <= l2->val) {
        l1->next = mergeTwoListsRecursive(l1->next, l2);
        return l1;
    } else {
        l2->next = mergeTwoListsRecursive(l1, l2->next);
        return l2;
    }
}
```

```java
class Solution {
    public ListNode mergeTwoLists(ListNode l1, ListNode l2) {
        if (l1 == null) {
            return l2;
        } else if (l2 == null) {
            return l1;
        } else if (l1.val < l2.val) {
            l1.next = mergeTwoLists(l1.next, l2);
            return l1;
        } else {
            l2.next = mergeTwoLists(l1, l2.next);
            return l2;
        }
    }
}
```

## 先等一下

累死我了，现在两版代码都摆在这了，先把它们并排：

| | 迭代版 | 递归版 |
| --- | --- | --- |
| 谁在挑下一个节点 | `while` 循环 | 函数自己 |
| 谁在推进指针 | 循环体里的 `l1 = l1->next` | 参数传递 |
| 谁在保管“已经拼好的那半条” | `tail` 指针 | 函数的返回值 |
| 每轮处理的节点数 | 1 个 | 1 个 |

看出来了吗，实际上**这两版代码干的事情一模一样**，都是“每次挑较小的那个节点接上去”，唯一的区别是“重复”这个动作是交给 `while` 还是交给函数调用栈。

而调用栈的价格就是我们前面算过的那些：每层一帧栈空间，加上跳转、返回的开销。对于以 21 题这一题而言：两版都能 AC，迭代版省 `O(n+m)` 的栈，递归版少写十来行，~~以及能让你更显得嘉豪~~。

好吧，但这不是我真正想问的。**为什么我会觉得归并这个动作和递归是一回事？**

## 归并排序里，“分”和“治”根本不是一个层次

回到刚才的归并排序，把我们前面那两个发现接起来看：

- 整个归并排序 = 把序列不断一分为二（**分**）+ 把两个有序段合成一个（**治**）
- `merge` 只管“治”。它拿到手的两个段**已经是有序的**，它压根不需要知道这两段是怎么变有序的
- 递归只出现在“分”这一步：`sort(left); sort(right); merge(...)`

> [!IMPORTANT]
> **归并排序 = 递归的“分” + 迭代的“治”。** 递归和迭代在这个算法里不是竞争关系，是两个层次、两个工序

所以，课上讲的两个有序链表的归并，CS61B 讲的 `Merge Sort`，力扣第 21 题，这三者用的**“治”是同一段代码**（双指针 + `while`）。它们看起来像，是因为它们本来就是同一个东西。而它们要不要用递归呢，这个判断的分歧不在“归并”上，只在**“要不要先把问题切成两半”**上，仅此而已。

而力扣第 21 题更是连“分”这一步都没有——它直接丢给你两个已经有序的表，课上也是如此，作业就不知道了。

## 那“分”这一步，能不能也写成循环？

当然ok。

前面那个数组的 `sortIterative` 就是。但问题在于：**同样的思路，在数组上只要三个下标，在链表上要三个辅助函数？**

### 数组：自底向上几乎零成本

数组能 `O(1)` 取长度、能按下标随机切分，`left`、`mid`、`right` 三个下标就是“分”的全部状态。所以自顶向下（递归）和自底向上（循环）在数组上是**等价的**，纯粹看你喜欢哪种写法。

顺带一提，数组归并的那个 `temp` 数组是省不掉的，因为合并时不能就地覆盖原数组；但**链表不用 `temp`，改指针本来就是就地操作**。这就是为什么同样是“自底向上归并排序”，数组那边空间是 `O(n)`，而链表这边能做到 `O(1)`。

### 链表：自底向上要额外付寻址的代价

链表不行。不能随机访问，所以切出长度为 `step` 的一段每次都得从头往前走 `step` 步；而且你得先遍历一遍求长度。这就是后面那个 `cut` 辅助函数存在的全部理由。

而且：**数组的递归是“用下标分”，链表的递归是“用指针分”。** 链表里 `head` 本身就是天然的分界点，递归下去的时候几乎不需要额外寻址；而自底向上的话，你得自己造出这些分界点来。

**所以“分”这一层选递归还是循环，很大程度不是口味问题，而是存储结构决定的**：

> [!TIP]
> 数组上：两者等价，随手写。
> 链表上：递归省事（`head` 就是断点），循环要额外付`O(n)`的走动代价和一份更长的代码。

**但链表上的递归还有一个数组上不存在的坑**

## 更正：链表的递归深度有两种形状，只有一种是危险的

我在前面说过一句“链表长度上限 5×10⁴，递归深度也到这个量级，有栈溢出的风险”（~~好吧其实是在重排链表那篇里说过，你也可以当我没说过~~）。这句话**只对一半的递归成立**。链表的递归其实有两种形状，它们的深度差了一个数量级：

### 形状一：链式递归，每层吃掉一个节点

```text
mergeTwoLists(l1, l2)
    ↓ 只推进了一个指针
mergeTwoLists(...)
    ↓
mergeTwoLists(...)
    ...
    ↓ 节点被一个一个吃掉
边界
```

深度 = 节点总数。21 题的递归版就是这个形状，深度恒为 `n + m`。

**这个形状才是会爆栈的那个。** 重排链表（143）里的 `weave` 也是这个形状，深度 = n，而那道题的 n 最大到 5×10⁴，所以我当时说“有栈溢出的风险”是对的。

### 形状二：分治递归，每层砍掉一半

```text
sortList(一整条)
    ├── sortList(左半)
    │       ├── sortList(左半的左半)
    │       └── ...
    └── sortList(右半)
```

深度 = $\log_2 n$。148 题是这个形状，n = 5×10⁴ 时深度只有 **17 层**，跟栈溢出没关系。

啊当然了，不是这样的话我们的`Merge Sort`还有什么意义呢，对吧。

> [!WARNING]
> “链表递归会爆栈”只在形状一里成立。把 148 的递归版当成危险写法是一个很常见的误会。

所以让我拷打自己前面说的话：

1. **空间账算错了。** 我说递归法“在空间复杂度上也比不上迭代法”，这在归并排序里被夸大了：数组那个 O(n) 的 `temp` 两版都省不掉，链表两版都不要 `temp`，递归版只多 17 帧栈。**真正拉开差距的只有 143 那种形状一的递归。**
2. **不是“迭代全胜”，是按递归形状决定了win or lose。** 148 的递归版比迭代版短一半，深度只有 17，日常首选就是它；迭代版的价值不在更快，而在能交出那句进阶要求：**O(1) 空间**。

提另外一个细节：21 题那种写法（`l1->next = mergeTwoLists(l1->next, l2)`）**不是尾递归**，返回值还要参与 `l1->next` 的赋值，编译器没法把它优化成循环。n 帧栈是实打实要花的。

## 148. 排序链表：把两版都写一遍

前文的神秘小数字，现在它来了。

[合并两个有序链表](https://leetcode.cn/problems/sort-list/description/)

题干：

> 给你链表的头结点 `head` ，请将其按 **升序** 排列并返回 **排序后的链表** 。
>
> 进阶：你可以在 O(n log n) 时间复杂度和常数级空间复杂度下，对链表进行排序吗？

**n ≤ 5×10⁴**，**进阶要求 O(1) 空间，记住这两个验收指标**

### 递归版：分治

找中点 → 断成两段 → 各自排序 → 归并。

:::tabs

```c
//归并部分直接用 21 题的那段迭代代码
struct ListNode* mergeTwoLists(struct ListNode* l1, struct ListNode* l2);

struct ListNode* sortList(struct ListNode* head) {
    if (head == NULL || head->next == NULL) return head;

    // 快慢指针找中点：fast 从 head->next 起步
    // 这样 slow 一定停在中点之前，保证右半段非空
    struct ListNode* slow = head;
    struct ListNode* fast = head->next;
    while (fast != NULL && fast->next != NULL) {
        slow = slow->next;
        fast = fast->next->next;
    }

    struct ListNode* right = slow->next;
    slow->next = NULL;   // 必须断链！不断的话两半永远分不开

    return mergeTwoLists(sortList(head), sortList(right));
}
```

```java
class Solution {
    public ListNode sortList(ListNode head) {
        if (head == null || head.next == null) return head;

        // 快慢指针找中点：fast 从 head.next 起步
        // 这样 slow 一定停在中点之前，保证右半段非空
        ListNode slow = head;
        ListNode fast = head.next;
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
        }

        ListNode right = slow.next;
        slow.next = null;   // 必须断链！不断的话两半永远分不开

        return mergeTwoLists(sortList(head), sortList(right));
    }

    // 21 题那段迭代归并，原样搬过来
    private ListNode mergeTwoLists(ListNode l1, ListNode l2) {
        ListNode dummy = new ListNode(0);
        ListNode tail = dummy;
        while (l1 != null && l2 != null) {
            if (l1.val <= l2.val) { tail.next = l1; l1 = l1.next; }
            else                  { tail.next = l2; l2 = l2.next; }
            tail = tail.next;
        }
        tail.next = (l1 != null) ? l1 : l2;
        return dummy.next;
    }
}
```

:::

时间 `O(n log n)`，空间 `O(log n)`（递归栈，n = 5×10⁴ 时也就 17 层）。

**这里有个特别容易写出来的 bug：直接用快慢指针返回的那个节点当中点。**

```c
// 错误写法
struct ListNode* mid = middleNode(head);
return mergeTwoLists(sortList(head), sortList(mid));
```

我们拿最简单的 `1 → 2` 试一下：`middleNode` 返回的是**左中点**，也就是节点 `1`，而 `sortList(head)` 要排的还是 `1 → 2` 这条完整的链，**同一个问题又交给了同一个函数，无限递归。** 所以分治链表题的不变式就两条：

- 断点必须真的把链**断成两条**（`slow->next = NULL`）
- 断完以后两段长度都**严格小于**原来的长度（所以右半段从 `slow->next` 开始，不能从 `slow` 开始）

只要这两条成立，递归一定会收敛到 `head->next == NULL`。

### 迭代版：自底向上

把“分”也改成循环：先数长度，然后 `step = 1, 2, 4, ...`，每轮把相邻两段并成一段。三个辅助函数分别负责“切”“并”“返回新尾巴”。

:::tabs

```c
// 从 head 起切出 step 个节点，返回剩余部分的头（切完把第一段的尾巴置空）
struct ListNode* cut(struct ListNode* head, int step) {
    if (head == NULL) return NULL;
    for (int i = 1; i < step && head->next != NULL; i++) {
        head = head->next;
    }
    struct ListNode* rest = head->next;
    head->next = NULL;
    return rest;
}

// 把 l1、l2 归并后接到 prev 后面，返回新的尾节点
struct ListNode* mergeAfter(struct ListNode* prev, struct ListNode* l1, struct ListNode* l2) {
    struct ListNode* tail = prev;
    while (l1 != NULL && l2 != NULL) {
        if (l1->val <= l2->val) { tail->next = l1; l1 = l1->next; }
        else                    { tail->next = l2; l2 = l2->next; }
        tail = tail->next;
    }
    tail->next = (l1 != NULL) ? l1 : l2;   // 剩下的一整条直接挂上
    while (tail->next != NULL) tail = tail->next;   // 走到真正的尾巴
    return tail;
}

struct ListNode* sortList(struct ListNode* head) {
    if (head == NULL || head->next == NULL) return head;

    int n = 0;
    for (struct ListNode* p = head; p != NULL; p = p->next) n++;   // 链表得先数长度

    struct ListNode dummy;
    dummy.next = head;
    // step 是“每段长度”：1、2、4……每轮把相邻两段并成一段
    for (int step = 1; step < n; step *= 2) {
        struct ListNode* prev = &dummy;      // 已排好部分的尾巴
        struct ListNode* cur  = dummy.next;  // 本轮起点
        while (cur != NULL) {
            struct ListNode* left  = cur;
            struct ListNode* right = cut(left, step);   // 切出左段
            cur = cut(right, step);                     // 切出右段，剩下的留给下一对
            prev = mergeAfter(prev, left, right);       // 归并后接回去
        }
    }
    return dummy.next;
}
```

```java
class Solution {
    public ListNode sortList(ListNode head) {
        if (head == null || head.next == null) return head;

        int n = 0;
        for (ListNode p = head; p != null; p = p.next) n++;   // 链表得先数长度

        ListNode dummy = new ListNode(0);
        dummy.next = head;
        // step 是“每段长度”：1、2、4……每轮把相邻两段并成一段
        for (int step = 1; step < n; step *= 2) {
            ListNode prev = dummy;      // 已排好部分的尾巴
            ListNode cur  = dummy.next; // 本轮起点
            while (cur != null) {
                ListNode left  = cur;
                ListNode right = cut(left, step);  // 切出左段
                cur = cut(right, step);            // 切出右段，剩下的留给下一对
                prev = mergeAfter(prev, left, right);
            }
        }
        return dummy.next;
    }

    // 从 head 起切出 step 个节点，返回剩余部分的头（切完把第一段的尾巴置空）
    private ListNode cut(ListNode head, int step) {
        if (head == null) return null;
        for (int i = 1; i < step && head.next != null; i++) {
            head = head.next;
        }
        ListNode rest = head.next;
        head.next = null;
        return rest;
    }

    // 把 l1、l2 归并后接到 prev 后面，返回新的尾节点
    private ListNode mergeAfter(ListNode prev, ListNode l1, ListNode l2) {
        ListNode tail = prev;
        while (l1 != null && l2 != null) {
            if (l1.val <= l2.val) { tail.next = l1; l1 = l1.next; }
            else                  { tail.next = l2; l2 = l2.next; }
            tail = tail.next;
        }
        tail.next = (l1 != null) ? l1 : l2;   // 剩下的一整条直接挂上
        while (tail.next != null) tail = tail.next;   // 走到真正的尾巴
        return tail;
    }
}
```

:::

时间 `O(n log n)`，空间 `O(1)`，进阶要求满足。

对比后我们发现：**递归版赢在短，迭代版赢在那个 O(1)**，而它们的 `merge` 是同一段代码。

## 怎么把这两种写法都练稳

**我将以最直白最不绕弯子的方式告诉你：先固定骨架，再练它们之间的翻译**。

### 单链表的递归只有一个模板

单链表的递归之所以显得抽象，是因为你在脑子里跑不动“回溯阶段”。但好在链表题的递归形状非常单一，因为链表天生就是“一个节点 + 后面一整条链”：

```text
f(链表) :
    边界：把最平凡的情况直接返回（通常是空链表或单节点）
    递归：先处理 head->next 那部分，拿到结果
    合体！：再决定 head 自己怎么接上去
```

绝大多数单链表题的递归版都在这个模板里填空：

```c
/* 21 合并两个有序链表 */
l1->next = mergeTwoLists(l1->next, l2);
return l1;

/* 203 移除链表元素 */
head->next = removeElements(head->next, val);
return head->val == val ? head->next : head;

/* 83 删除排序链表中的重复元素 */
head->next = deleteDuplicates(head->next);
return head->val == head->next->val ? head->next : head;
```

三个都是同一个形状：**先把后面的处理干净，再决定自己留不留。** 这就是模板的全部。

反转方向的那一类（206、24、143）属于变体：因为 `head` 自己要被翻过去，返回的“新头”不再是 `head`，所以**必须先把递归的返回值接住**：

```c
/* 206 反转链表 */
struct ListNode* newHead = reverseList(head->next);
head->next->next = head;
head->next = NULL;
return newHead;
```

你看，就多记一个“谁是新的头”而已。

### 迭代的三条铁律

1. **虚拟节点**。只要可能动到头节点（合并、删除、交换、分割），开场就 `dummy.next = head`，收尾 `return dummy.next`。它把“第一个节点”这个特例抹掉了，代码里能少一半 `if`。
2. **先存后断**。`next = cur->next` 必须写在 `cur->next = ...` 之前。指针一断，后面的节点就找不回来了。
3. **剩余整条接**。循环退出时必定有一条链空了，另一条还有剩，这时**把剩下那一条整条挂上去**（`tail->next = l1 ? l1 : l2`），O(1) 解决。

让我再加半条：**动手前先想清楚最后返回谁**（`dummy.next` / `prev` / `newHead`），这个真是血泪教训。

### 两种写法互相翻译

| 迭代里 | 递归里 |
| --- | --- |
| 循环变量（`l1`、`l2`） | 函数参数 |
| 累加器（`tail` 指向的那条链） | 函数的返回值 |
| 循环条件 | 边界判断 |
| 循环体一次推进 | 递归下一层 |
| 循环结束时剩余的那条 | 边界直接返回的那条 |

**递归 → 迭代**：把参数降级成循环变量，把返回值降级成一个显式的累加器。21 题里参数 `l1, l2` 就变成循环里的 `l1, l2`，“返回值”就是 `tail->next` 挂着的那条链。

**迭代 → 递归**：把循环不变式念出来，它天然就是递归契约。21 题迭代版的不变式是：

> [!NOTE]
> 循环开始时，`tail` 指向已拼好部分的末尾，`l1` 和 `l2` 指向各自还没处理的部分。

换成递归契约就是：“`merge(l1, l2)` 返回把 `l1`、`l2` 全部拼好之后的结果”。**循环不变式就是递归的参数和返回值**，这句话在链表题上几乎是**逐字成立**的。

如果一个循环每轮只“吃掉”一个元素，那它一定能机械地改成链式递归；如果每轮在做“两端同时往中间缩”或者“重新分配区间”这类事，那它对应的是分治递归（或者根本不该递归）。

### 两栏法验算

对于两种写法而言，它们各有各的脑子跑不动的地方，也各有对应的纸面办法：

- **写迭代时，画状态表**。列名就是所有会变的变量：`轮次 | l1 | l2 | 取谁 | tail 之后的结果链`，每轮填一格。这跟你写接雨水时一排一排数雨水是同一件事。
- **写递归时，画调用栈，从最内层往外填返回值**。递归难就难在回溯阶段的状态，画出栈之后，从下往上填返回值就退化成了一张普通表格，和迭代那份一模一样。

> [!TIP]
> 验算到最后其实是同一张表：迭代**从左往右**填，递归**从下往上**填。

当你拿到任何一道链表题，先回答三个问题再动手：

- **有“分”吗？** 把问题切成两半，还是从两端往中间夹？
- **要递归的话是哪个形状？** 每层吃一个节点（深度 `n`，看规模决定要不要躲），还是砍一半（深度` log n`，放心写）？
- **“治”的部分照抄模板，不重写。** 它是迭代的。

## 回到最初的问题

**归并链表，递归还是迭代？**

**归并这个动作永远是迭代的。** 这不是风格偏好：归并本身就是一趟线性扫描，它没有任何自相似结构，递归进去只会平白多出 n 帧栈。递归只属于“分”。

| 场景 | 有“分”吗 | 递归深度 | 用哪个 |
| --- | --- | --- | --- |
| 21 合并两个有序链表 | 没有 | $n + m$（但 n ≤ 50） | 两版随便，迭代版更贴近本质，也更好扩成 k 路归并 |
| 148 排序链表 | 有 | $\log n$ | 递归版省事；要 O(1) 空间就自底向上 |
| 143 重排链表 | 没有 | $n$（n ≤ 5×10⁴） | 别递归，快慢指针 + 反转 |
| 数组归并排序 | 有 | $\log n$ | 自底向上，本来就是循环的主场 |

至于开头那个“名字这么像，用的方法是不是也一样”——它们的“治”是同一段代码，只是“分”的层次不一样。

**名字像，是因为它们本来就是同一个东西。**
