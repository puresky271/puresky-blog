说实话，我是一个对他人的耐心不足的人，我尤为反感的一件事情就是反复解释基本的记忆性的概念和操作。

还是让我来举一个例子，我最近因为自己所在学生组织的关系一直在整理有关于Git的笔记，我们当时在对新生招新时的胃口其实很大——想要那些准大一的学弟学妹们能够通过自己的学习畅所欲言Git的相关知识。但实际上，就我负责面试的人而言，绝大部分的人只记住了以下的几个命令：

```bash
git init

git add .
#甚至还知道.，不赖（
git commit

git reset
```

有一些情况好的，可能还能记得下什么是`git branch`，什么是`checkout`，什么是`merge`。啊当然了，我们也不可能要求对面的人去深入讲解其中的原理，但是就对于最多大约有整整4周的面试准备期而言，这记下来的也...太少了吧？

而且当时让我感到十分诡异的是，**有许多人甚至连上述的四个基本命令都记不住，但是他们反而知道以下这个命令：**

```bash
git clone " "
#一个连git init都不知道的人，反而会知道git clone的用法
```

不过我也很快想明白了这件事的原因——当时我们在其他部分的题目中有关于仓库资料获取的描述，并给出了`git clone "仓库地址"`的命令，直接写在了题干里面。**对的，这就是他们唯一可以直接看到的git命令，所以他们就只记住了这一个。**你说这好不好笑，看起来要是我们当时直接把Git的相关命令列出一张表格放到题干里面，直接说：“嘿，请把它们背下来，到时候展示给我们看”，那样的话情况会好很多吗，大概吧。

不过我实际想说的是：**在缺乏笔记或可以定期查阅的示例材料时，我们的即时记忆能力还能剩下多少？**

这就像，一个agent在不依靠用户的即时反馈和外部的RAG检索工具的时候，它单靠上下文/KV cache，能“记得”多少东西？

**在AI时代，你需要扩大你的上下文窗口**

## 我们能做到“看一眼就记下吗？”
在阿特金森与希夫林提出的经典的**记忆的三级加工模型**当中，我们将记忆分为

- **感觉记忆（Sensory Memory / 瞬时记忆）**：这是刺激停止后，感官在极短时间内保留原始物理信息的过程。通常在 0.25 秒到 2 秒 左右。
- **短时记忆（Short-term Memory）与 工作记忆（Working Memory）**：通过对感觉记忆中获得注意的信息进行临时储存和意识加工，可以延长到15 到 30 秒 左右
- **长时记忆（Long-term Memory）**：信息经过深度加工、巩固后长期保存的系统，容量理论上近乎无限。

啊当然了，我们还有另一个经典的分类：工作记忆（Working Memory），情景记忆（Episodic Memory），语义记忆（Semantic Memory），这里不再赘述。

但是我会发现，我平时有时候在刷视频的时候会对一个概念/一个知识点看一眼直接记住，emm...这似乎不太符合上述的记忆理论。

于是我查了一下相关的原理，大概是这样的：书本上的一句话可能很抽象，但短视频里有生动的动画、主播的语气、背景音乐、实物展示。大脑的枕叶（视觉）、颞叶（听觉）和额叶（理解）同时被激活，形成多个维度的记忆提取线索。以后你只要想到那个画面或声音，就能把概念顺藤摸瓜拽出来。

另一个方面：那些被我们通过这种方式记住的知识，通常具有极强的反直觉性或极高的新奇度。当一个信息打破了你的预期的时候，大脑的黑质/腹侧被盖区（VTA）会释放多巴胺。它会给海马体发送明确的神经信号：“这个信息很有价值，立刻写入长期记忆！”

> [!NOTE]
> 认知心理学家佩维奥（Paivio）提出过著名的“双重编码理论”：单纯的语言符号很难记，但语言＋视觉图像＋动态情境能形成双重甚至多重编码。

对的，我自认为我是一个对很多小知识点能做到“某一天看到过一次”后就能在之后复述出来，变成我的谈资之一的人。虽然说这种知识在大部分的时候就只仅仅是谈资而已，但回到我们先前的那个关于Git的例子——假设你就仅仅是一个为了来应付我这个面试官的新生（~~这在那种情景下也没什么不好的~~），如果你能通过这种方式记下一些Git的命令，那我觉得你也完全达到了你的目标了，不是吗？

所以，我其实认为这种类型的记忆形式没什么不好的，甚至我认为它是一个AI时代必备的技能之一，因为如果我们回头来看这种记忆产生的那些条件：

- 语言＋视觉图像＋动态情境
- 反直觉性 + 新奇度
- 人自己的主动参与过程

**你平时和AI交流问题或是Vibe Coding的过程不就完美符合这些条件吗！**

> [!WARNING]
> 当然了，AI有幻觉，AI给出的答案未必是正确的，甚至说在大部分时间下是不完整的，但这是另一个需要解决的问题，我们当下不讨论这个。

事实上，我目前对很多的计算机/工程的底层的知识就是来源于我在搭空中楼阁而发现不可，回去向AI询问地基的时候了解到的。

AI交互和Vibe Coding彻底解放了你记“宏观认知”的能力。 它通过新奇感、主动提问、极短反馈，让你对**“概念、逻辑、全局架构”**形成了极其牢固的记忆。

但我还要说的是，当你读懂了AI的解释，或者看着代码跑通的时候，大脑的认知流畅度是极高的。而高流畅度会欺骗大脑，让你产生一种“我已经彻底学会了”的错觉。**但“能看懂别人的推导”和“自己大脑里构建出神经回路”完全是两码事。**

这也就是我觉得很多时候纯依赖AI学CS会废掉一个人的原因

但是这种记忆机制本身依旧值得应用，我们把AI给出的内容分为两类：

你可以试着一眼记住的：

- 概念的“真名”（专业术语与高阶词汇）
- “权衡取舍”与决策理由
- 边界条件与“坑的形状”
- 高阶工作流与排错思路

千万不要觉得你自己记住的东西：

- 具体的语法、API参数和正则表达式
- 代码的具体逐行实现
- 各种繁琐的配置格式与环境命令
- 纯事实性的孤立数值与文档细节

## 人的上下文窗口变大后的好处是？
之前在一个AI交流群里面，有一个大佬非常受我们的推崇。有一天，他被问到为什么自己的知识面可以如此广博，以及对问题分析十分透彻时，人家也就总结了这么一句：

> 我的上下文窗口比较大

这也就是这篇文章的标题的灵感。

当然了，人家除了上下文窗口大之外，**注意力机制应该也够强**。不过我在这里并不想再像那些公众号的鸡汤文一样向你逐一罗列一遍上下文窗口变大的好处，我是一个学AI的人，还是让我用人与AI的交互来举一个例子：

现在的coding agent的发展如火如荼，而离开了入门阶段后，我经常被问到的一个问题就是：**该怎么能让不同的agent（我不是指同一个agent平台内AI给自己开的子代理）之间在工作之间互相交流和监督呢？**

> [!NOTE]
> 关于这一点，我们在未来会有专门的文章来解释

我将以最直白最不绕弯子的方式告诉你：**我平时就是人肉来充当这个在AI中间的中转。**

这会很原始吗？我觉得还好，因为一方面如果你要对AI的产物全权负责的话，全程紧盯着AI的`workflaw`和`COT`确实是很有必要且很有好处的。另外的一点就是：**子代理的上下文很少**，因为它一开始能拿到的就只是父代理所编写的一段压缩了信息之后的长提示词，在着之后它就得自己去执行代码检索以及查看各种脚本的输出来“再一次理解任务”。

> [!TIP]
> 事实上，开启子代理本身就是一种用信息熵的损失来换取父代理注意力集中和执行效率的方式，而且开启子代理还会降低你的缓存命中率。

**但是父代理，哦，我是说，人的上下文窗口可是非常大的**——你和LLM不一样，你又不是一个没有内部状态的函数，需要不断重构你的历史信息。你完全可以利用这个优势来指导不同agent之前的并行工作，乃至于跨平台的agent协作。

当然，这很累，但是这是有必要且非常有效的

agent 以为自己理解了另一个 agent 的意图，但其实它们只是在互相消费对方生成的幻觉。而当你肉身切入这个回路时，情况就完全不同了。

你之所以能充当这个不可替代的中转路由，就是因为你的**“全局上下文”是天然持久化且具有拓扑结构的**。在你的这个大窗口里，不仅塞着刚刚代码报错的那二十行堆栈，还常驻着一堆 LLM 根本看不见的隐式的东西，比如：

- 这个系统为什么两周前要推翻原来的架构？
- 为什么某段看起来很蠢的代码其实是为了绕过一个老旧 SDK 的 bug，绝对不能让重构 Agent 给“顺手优化”掉？
- 这个函数真的被调用了吗？
- 这个地方的注释是不是不能硬编码一些敏感内容？

**你看，你是那个唯一拥有完整状态机的人，你需要扩大你的上下文窗口**

所以利用起我们在上一个部分所提到的记忆机制，尝试在一个对话窗口内实时的去记住一些东西，它可以是短期的——你将其带到另一个AI的对话窗口后这条记忆的使命也就结束了。它可以且应该是长期的——你今天在和一个agent的协作中记下了一个能让你的项目变得更好的知识点，等到明天，甚至，更远的将来，你在另一个地方给agent连上了你的工作区，它还在你的上下文里面，可能被压缩了，但依然是有效的。

## 写在最后
在AI时代，留给我们思考，学习，乃至记忆的时间都变少了，但是对于我们，特别是对于我这种工科的学生而言，我们需要无时无刻的保持自我的思考，让你的大脑成为那条在海水之间游动的金枪鱼。而这就需要你的context window从256k升级到512k，800k，乃至1M。

**你需要扩大你的上下文窗口，这不仅是对你自己负责，也能让你能对你的AI负责，AI能对你负责，最后你能对与你一起合作的人和你周围的环境负责。**
