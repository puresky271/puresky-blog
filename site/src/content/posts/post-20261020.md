**并查集（Union-Find，也叫 Disjoint Set Union，简称 DSU）**是一个专门用来维护若干个互不相交的集合，并快速判断元素之间是否属于同一个集合的数据结构。

顾名思义，并查集支持两种操作：

- 合并（Unite）：合并两个元素所属集合（合并对应的树）
- 查询（Find）：查询某个元素所属集合（查询对应的树的根节点），这可以用于判断两个元素是否属于同一集合

实话说，并查集的核心思想很简单：**从每个集合选出一个代表，通过代表来判断集合之间的关系。需要合并集合时，就把两个集合连接起来。**本文将对并查集的原理，应用和优化做介绍。

## 并查集的现实意义

并查集并不抽象，它要解决的问题在生活里随处可见。我们先从一个班的同学说起。

也就是说，此时一共有 6 个小组，每个小组里只有一个人。

接下来，发生了几件事：

- A 和 B 成为了朋友；
- C 和 D 成为了朋友；
- 接着，B 和 C 也成了朋友；
- 最后，E 和 F 也成了朋友。

这里我们暂时规定一条规则：**两个人成为朋友，就把他们各自所在的小组合并**。

按这条规则走一遍：

- A 和 B 成为朋友，$\{A\}$ 与 $\{B\}$ 合并成 $\{A,B\}$；
- C 和 D 成为朋友，$\{C\}$ 与 $\{D\}$ 合并成 $\{C,D\}$；
- 然后是 B 和 C：此时 B 已经在 $\{A,B\}$ 里，C 已经在 $\{C,D\}$ 里，所以合并的是这两个小组；
- 最后是 E 和 F，$\{E\}$ 与 $\{F\}$ 合并成 $\{E,F\}$。

### 并查集要解决的问题

从这个例子中抽象出来的话，你会发现我们其实只有两种需求。

**第一，我们希望快速判断两个元素是否属于同一个集合。**例如：

- A 和 D 是不是同一个小组？
- A 和 E 是不是同一个小组？

**第二，我们希望在出现新的关系时，能够合并两个集合。**例如：

- B 和 C 成为朋友后，合并他们各自所在的小组；
- D 和 E 成为朋友后，再合并两个小组。

这两个需求，分别对应并查集的两个核心操作：

| 操作 | 含义 |
| :--- | :--- |
| 查询（Find） | 判断一个元素属于哪个集合 |
| 合并（Union） | 将两个集合合并成一个集合 |

这就是「并查集」这个名字的来源：**合并集合，查询集合**。

> [!NOTE]
> 并查集的英文叫 Union-Find，也叫 Disjoint Set Union（DSU）：Union 是合并，Find 是查询。有的资料把合并写成 Unite 或 Merge，说的都是同一件事。

对应的父子关系是：

- `parent[B] = A`：B 的父结点是 A；
- `parent[C] = A`：C 的父结点也是 A；
- `parent[D] = B`：D 的父结点是 B；
- `parent[A] = A`：A 的父结点是它自己。

> [!TIP]
> **一个根结点通过"父结点就是自己"来标记**，我们称它为**根结点**（root）。


那么集合里的其它元素怎么找到这个根结点呢——**沿着父结点一直往上走就可以了。**

比如 D：D 的父结点是 B，B 的父结点是 A，而 A 的父结点是它自己，走不动了，所以根结点就是 A：

$$D \longrightarrow B \longrightarrow A$$

于是我们可以说：D 所在集合的代表元素是 A，B 所在集合的代表元素是 A，C 所在集合的代表元素也是 A。**虽然 D 并没有直接指向 A，但它最终能够沿着父结点抵达 A。**

于是，**只要两个元素最终找到同一个根结点，我们就认为它们属于同一个集合**——这就是并查集判断集合归属的关键。

### 用树方便地合并集合

假设现在有两个独立的集合：$\{A,B,C,D\}$（根结点是 A）和 $\{E,F\}$（根结点是 E）。

`parent[E] = A;`

### 代码存储

说到树，你可能会想到：

> 既然是一棵树，是不是应该像普通的树那样，为每个结点创建一个对象，再维护指针？

当然可以，但并查集有一种更简单的实现方式：**直接用一个数组 `parent`，存放每个结点的父结点编号。**

这里为了方便演示，我们假设 A、B、C、D、E、F 的编号分别是 0、1、2、3、4、5。回到**刚才还没合并的那两棵树**，把它们记进一个数组就是：

:::tabs
```java
// 下标是元素编号，值是父结点编号
// A = 0, B = 1, C = 2, D = 3, E = 4, F = 5
int[] parent = {0, 0, 0, 1, 4, 4};
```

```c
/* 下标是元素编号，值是父结点编号 */
/* A = 0, B = 1, C = 2, D = 3, E = 4, F = 5 */
int parent[] = {0, 0, 0, 1, 4, 4};
```
:::

数组的下标代表元素本身，数组里的值代表它的父结点。逐项对应：

| 元素编号 | 元素 | parent 值 | 含义 |
| :--- | :--- | :--- | :--- |
| 0 | A | 0 | A 的父结点是 A，它是根结点 |
| 1 | B | 0 | B 的父结点是 A |
| 2 | C | 0 | C 的父结点是 A |
| 3 | D | 1 | D 的父结点是 B |
| 4 | E | 4 | E 的父结点是 E，它是根结点 |
| 5 | F | 4 | F 的父结点是 E |

第一，`parent[3] = 1` 表示编号为 3 的 D，它的父结点是编号为 1 的 B。

第二，`parent[4] = 4` 表示 E 的父结点就是它自己，所以 E 是第二个集合的根结点。

## 查找与合并

现在我们已经把集合存成了一个 `parent` 数组，现在就差最后一步：在这个数组上把**查找**和**合并**写出来。

### `find`：从元素走到根

查找的思路就是那句话：**沿着父结点一直往上走，走到"父结点是自己"的那个结点，它就是根。**

如下：

:::tabs
```java
/** 查找：沿着父结点往上走，直到父结点是自己的那个结点 */
int find(int x) {
    while (parent[x] != x) { // 父结点不是自己，说明 x 还不是根
        x = parent[x];       // 跳到父结点，继续往上找
    }
    return x;
}
```

```c
/* 查找：沿着父结点往上走，直到父结点是自己的那个结点 */
int find(const int parent[], int x) {
    while (parent[x] != x) { /* 父结点不是自己，说明 x 还不是根 */
        x = parent[x];       /* 跳到父结点，继续往上找 */
    }
    return x;
}
```
:::

来看这个`while`循环：只要 `parent[x]` 不是 `x`，就说明 x 还没有走到根，于是令 `x = parent[x]`，跳到父结点上接着找；一旦 `parent[x] == x`，循环结束，此时的 x 就是根。

顺带一提，`find` 也可以写成递归：`return parent[x] == x ? x : find(parent[x]);`——意思完全一样。但如果树很深的话递归会一层层压栈，所以还是更推荐上面这种循环写法。

查找的耗时取决于**树的高度**：从元素走到根要跳几步，就是几层，所以 `find` 的复杂度通常记作 $O(h)$（$h$ 是树高）。如果树长歪了、退化成一条长长的链，$h$ 最坏可以等于糟糕的 $n$。

### `unite`：把根挂到根上

合并的关键是：**不要动元素，只动根。**

先把两个元素的根找出来，然后分两种情况：

- 两个根是同一个结点：说明它们本来就在一个集合里，什么也不用做；
- 两个根不是同一个结点：把其中一个根挂到另一个根下面，比如 `parent[rootB] = rootA`。

如下：

:::tabs
```java
/** 合并：先找到两个集合的根，再把其中一个根挂到另一个根上 */
void unite(int a, int b) {
    int rootA = find(a);
    int rootB = find(b);
    if (rootA == rootB) {  // 本来就在同一个集合里，不用合并
        return;
    }
    parent[rootB] = rootA; // 只改这一格
}
```

```c
/* 合并：先找到两个集合的根，再把其中一个根挂到另一个根上
```

```java
// UnionFindDemo.java：并查集的查找与合并
class UnionFind {
    int[] parent; // 下标是元素编号，值是父结点编号

    UnionFind(int n) {
        parent = new int[n];
        for (int i = 0; i < n; i++) {
            parent[i] = i; // 一开始每个人都是自己集合的根
        }
    }

    /** 查找：沿着父结点往上走，直到父结点是自己的那个结点 */
    int find(int x) {
        while (parent[x] != x) { // 父结点不是自己，说明 x 还不是根
            x = parent[x];       // 跳到父结点，继续往上找
        }
        return x;
    }

    /** 合并：先找到两个集合的根，再把其中一个根挂到另一个根上 */
    void unite(int a, int b) {
        int rootA = find(a);
        int rootB = find(b);
        if (rootA == rootB) {  // 本来就在同一个集合里，不用合并
            return;
        }
        parent[rootB] = rootA; // 只改这一格
    }

    /** 把查找的过程打印出来，方便观察 */
    void traceFind(int x) {
        System.out.print("find(" + x + ")：");
        while (parent[x] != x) {
            System.out.print("parent[" + x + "] = " + parent[x] + " → ");
            x = parent[x];
        }
        System.out.println("parent[" + x + "] = " + x + "（是自己），所以根是 " + x);
    }

    /** 打印数组，方便观察每一步的变化 */
    void print() {
        System.out.print("parent = {");
        for (int i = 0; i < parent.length; i++) {
            if (i > 0) {
                System.out.print(", ");
            }
            System.out.print(parent[i]);
        }
        System.out.println("}");
    }
}

        System.out.println("依次合并：");
```

```c
#include <stdio.h>

#define N 6 /* A = 0, B = 1, C = 2, D = 3, E = 4, F = 5 */

/* 查找：沿着父结点往上走，直到父结点是自己的那个结点 */
int find(const int parent[], int x) {
    while (parent[x] != x) { /* 父结点不是自己，说明 x 还不是根 */
        x = parent[x];       /* 跳到父结点，继续往上找 */
    }
    return x;
}

/* 合并：先找到两个集合的根，再把其中一个根挂到另一个根上
 * 注意：union 在 C 里是关键字，所以这个函数叫 unite */
void unite(int parent[], int a, int b) {
    int rootA = find(parent, a);
    int rootB = find(parent, b);
    if (rootA == rootB) { /* 本来就在同一个集合里，不用合并 */
        return;
    }
    parent[rootB] = rootA; /* 只改这一格 */
}

    printf("find(%d)：", x);

        printf("parent[%d] = %d → ", x, parent[x]);

    }

}
```

同样是这 6 个人构成的集合：

- 在扁的树里，`find(A)` 走 1 步就到根；
- 在这条链上，`find(A)` 要走 5 步：$A \longrightarrow B \longrightarrow C \longrightarrow D \longrightarrow E \longrightarrow F$。

如果 $n$ 个元素正好排成一条链，树高就是 $n$，`find` 的复杂度会退化成 $O(n)$——每一次查询都像在数组里一路找过去。

但麻烦的地方在于，**合并的顺序是由输入数据决定的，我们没法挑**。所以我们不能指望"运气好、树长得扁"，只能**主动做点事情把树压矮。**

## 路径压缩

想想看：**既然已经辛辛苦苦走到了根，那就顺手把走过的路都接短一点。**

怎么做呢？当我们找到某个元素所属集合的根之后，**把查找路径上的结点直接挂到这个根下面。**这样下次再查这条路上的任何一个元素的时候**一步就能到根。**

我去强强？？这么做合理吗，嗯，这是合理的。因为并查集只关心"元素属于哪个集合"，并不关心树长什么样。只要最后找到的还是同一个根的话集合关系就没有变，至于形状怎么改都行。

查找 E 的过程是 $E \to D \to C \to B \to A$，一共要走 4 条边。可问题是查完之后我们已经知道：E、D、C、B 都属于 A 所代表的集合，**那下次再查 E凭什么还要把 D、C、B 重新走一遍？**

对，这当然是没必要的，于是我们把这几个结点的父结点全都改成 A：E、D、C、B 都直接指向 A。之后查这几个元素中的任何一个都是 1 步到根。

这也就是我们说的路径压缩了。要注意**路径压缩并不是一次性把所有结点永久钉死在根下面**，而是在查找的过程中走到哪儿压到哪儿。

### 递归写法

最常见的写法是递归，只有这么几行：

:::tabs
```java
/** 查找 + 路径压缩：返回 x 所在集合的根，顺手把路径上的结点挂到根上 */
int find(int x) {
    if (parent[x] != x) {            // x 不是根
        parent[x] = find(parent[x]); // 先找到根，再让 x 直接指向根
    }
    return parent[x];
}
```

```c
/* 查找 + 路径压缩：返回 x 所在集合的根，顺手把路径上的结点挂到根上 */
int find(int parent[], int x) {
    if (parent[x] != x) {                    /* x 不是根 */
        parent[x] = find(parent, parent[x]); /* 先找到根，再让 x 直接指向根 */
    }
    return parent[x];
}
```
:::

第一步，`if (parent[x] != x)`：先判断 x 是不是根。是根就不用往上了，不是根，才继续往下执行。

第二步，`parent[x] = find(parent[x]);`：先用 `int root = find(parent[x]);` 找到父结点那一路的根，再用 `parent[x] = root;` 让 x 直接指向这个根。

第三步，`return parent[x];`：因为上一行已经把 `parent[x]` 改成了根，所以这里直接返回就是根。

换个说法：向下递归时，每一层都在问"我的父结点往上能走到哪个根"，等根给出答案，每一层就顺手把自己的 `parent` 改成那个根。

## 按秩合并

如果说路径压缩是在**查找**时救场，那么按秩合并就是在**合并**时预防：**从一开始就别让树长高。**

### 朴素合并的问题

在之前的 `unite` 中，我们在拿到两个根之后直接让`parent[rootB] = rootA`。它总是把第二棵树的根挂到第一棵树的根下面，完全不看两棵树谁高谁矮。

当然这样写本身没有逻辑错误，但运气不好时就会造出高树。比如按这个顺序合并 5 个元素：

`unite(1, 0)`、`unite(2, 1)`、`unite(3, 2)`、`unite(4, 3)`

和先前所言一致：它每次都是把"已经建好的整棵树"挂到"新来的单个人"下面，结果就是一条链 $0 \to 1 \to 2 \to 3 \to 4$，查 0 要走 4 条边——这正是上一节那张"最坏情况"图里的形状。

但是如果我们每次合并都能让**矮的树挂到高的树下面**，树就很难长高。这就是按秩合并的出发点。

### rank

你可以直接把rank理解成**一个用来估计树高的指标**，帮我们判断合并时谁该挂在谁下面。

规则只有三条：

- 树 A 的 rank 比树 B 小：把 A 挂到 B 下面；
- 树 A 的 rank 比树 B 大：把 B 挂到 A 下面；
- 两棵树的 rank 相等：随便选一个当新根，然后把新根的 rank 加 1。

等等，第三条为什么要加 1？因为两棵一样高的树接起来，新树确实会比原来多一层，而矮树挂到高树下面时，高树的高度并不会变。

### 实现

把三种情况组合起来：

:::tabs
```java
/** 按秩合并：让矮树挂到高树下面 */
void unite(int a, int b) {
    int rootA = find(a);
    int rootB = find(b);
    if (rootA == rootB) { // 本来就在同一个集合里
        return;
    }
    if (rank[rootA] < rank[rootB]) {        // A 更矮，A 挂到 B 下面
        parent[rootA] = rootB;
    } else if (rank[rootA] > rank[rootB]) { // B 更矮，B 挂到 A 下面
        parent[rootB] = rootA;
    } else {                                // 一样高，B 挂到 A 下面
        parent[rootB] = rootA;
        rank[rootA]++;
    }
}
```

:::

需要注意的是：**比较的是 `rank[rootA]` 和 `rank[rootB]`，不是 `rank[a]` 和 `rank[b]`。**因为 a 和 b 可能只是树中间的普通结点，真正要连接的是两个集合的根。

另外，别忘记只有两个根的 rank 相等时才加 1。

| 比较结果 | 合并方式 | 新根的 rank |
| :--- | :--- | :--- |
| A 小于 B | A 挂到 B 下面 | 不变 |
| A 大于 B | B 挂到 A 下面 | 不变 |
| A 等于 B | B 挂到 A 下面 | A 的 rank 加 1 |

### 但问题在于：rank 是树高吗？

我将以最直接最不绕弯子的方式告诉你：**不完全是。**

在没有路径压缩时，按上面的规则维护出来的 rank确实就等于树的实际高度（按边数算）。但**加了路径压缩之后rank就不一定等于当前树的高度了**：比如一棵 rank 为 3 的树被压过之后实际可能只剩 1 层。

那要不要把 rank 改回 1呢？不用。

rank 的用途是指导合并时挑根，不是随时精确测量树高。而且路径压缩只会让树变矮而不会让树变高，保留旧的 rank 依然能保证复杂度分析成立。

**所以把 rank 理解成"一个用来控制树高的历史指标"就好，不用把它当成实时的树高计数器。**

## 两种优化的区别

| | 路径压缩 | 按秩合并 |
| :--- | :--- | :--- |
| 什么时候起作用 | `find` 时 | `unite` 时 |
| 做了什么 | 把路径上的结点直接挂到根上 | 让矮树挂到高树下面 |
| 优化的是 | 已经走过的路 | 还没长出来的高度 |
| 效果 | 树被压扁 | 树不容易长高 |

一般来说，**两个一起用**才是并查集的经典形态：$n$ 个元素、$m$ 次操作，总时间复杂度 $O(m\,\alpha(n))$，均摊下来近似常数。

顺带一提，**按大小合并**（Union by Size）是另一个常见选择：它维护的不是 rank，而是每棵树的元素个数，每次把小集合挂到大集合下面，同样能有效控制树高。

### 两个都用上

```java
// OptimizedDemo.java：路径压缩 + 按秩合并
class UnionFind {
    int[] parent; // 下标是元素编号，值是父结点编号
    int[] rank;   // 每个根结点的 rank

    UnionFind(int n) {
        parent = new int[n];
        rank = new int[n];
        for (int i = 0; i < n; i++) {
            parent[i] = i; // 一开始每个人都是自己集合的根
        }
    }

    /** 查找 + 路径压缩：返回 x 所在集合的根，顺手把路径上的结点挂到根上 */
    int find(int x) {
        if (parent[x] != x) {            // x 不是根
            parent[x] = find(parent[x]); // 先找到根，再让 x 直接指向根
        }
        return parent[x];
    }

    /** 按秩合并：让矮树挂到高树下面 */
    void unite(int a, int b) {
        int rootA = find(a);
        int rootB = find(b);
        if (rootA == rootB) { // 本来就在同一个集合里
            return;
        }
        if (rank[rootA] < rank[rootB]) {        // A 更矮，A 挂到 B 下面
            parent[rootA] = rootB;
        } else if (rank[rootA] > rank[rootB]) { // B 更矮，B 挂到 A 下面
            parent[rootB] = rootA;
        } else {                                // 一样高，B 挂到 A 下面
            parent[rootB] = rootA;
            rank[rootA]++;
        }
    }

    /** 不压缩的查找：只用来做"朴素合并"的对比实验 */
    int findNoCompress(int x) {
        while (parent[x] != x) {
            x = parent[x];
        }
        return x;
    }

    /** 朴素合并：不看高度，直接把 b 的根挂到 a 的根下面（只用来做对比） */
    void uniteNaive(int a, int b) {
        int rootA = findNoCompress(a);
        int rootB = findNoCompress(b);
        if (rootA != rootB) {
            parent[rootB] = rootA;
        }
    }

    /** 打印从 x 到根的路径（不压缩） */
    void printPath(int x) {
        System.out.print("  路径：");
        while (parent[x] != x) {
            System.out.print(name(x) + " → ");
            x = parent[x];
        }
        System.out.println(name(x) + "（根）");
    }

    /** 当前树的高度（按边数算） */
    int height() {
        int h = 0;
        for (int i = 0; i < parent.length; i++) {
            int depth = 0;
            int x = i;
            while (parent[x] != x) {
                x = parent[x];
                depth++;
            }
            h = Math.max(h, depth);
        }
        return h;
    }

    /** 打印数组 */
    void print() {
        System.out.print("parent = {");
        for (int i = 0; i < parent.length; i++) {
            if (i > 0) {
                System.out.print(", ");
            }
            System.out.print(parent[i]);
        }
        System.out.println("}");
    }

    static String name(int i) {
        return String.valueOf((char) ('A' + i));
    }
}

public class OptimizedDemo {
    public static void main(String[] args) {
        // A = 0, B = 1, C = 2, D = 3, E = 4
        System.out.println("一、朴素合并：只看参数，不看高度");
        UnionFind uf = new UnionFind(5);
        uf.uniteNaive(1, 0); // A 挂到 B 下面
        uf.uniteNaive(2, 1); // 这一下把 A、B 整棵树挂到了 C 下面
        uf.uniteNaive(3, 2);
        uf.uniteNaive(4, 3);
        System.out.print("  ");
        uf.print();
        System.out.println("  树高：" + uf.height());
        System.out.println();

        System.out.println("二、带路径压缩的 find(A)");
        uf.printPath(0);
        System.out.println("  根是 " + UnionFind.name(uf.find(0)));
        System.out.print("  压缩后：");
        uf.print();
        System.out.println("  树高：" + uf.height());
        System.out.println("  再查一次 A：" + UnionFind.name(uf.find(0)) + "（1 步就到）");
        System.out.println();

        System.out.println("三、同样这四个合并，改用按秩合并");
        UnionFind uf2 = new UnionFind(5);
        uf2.unite(1, 0);
        uf2.unite(2, 1);
        uf2.unite(3, 2);
        uf2.unite(4, 3);
        System.out.print("  ");
        uf2.print();
        System.out.println("  树高：" + uf2.height());
    }
}
```

```c
#define N 5 /* A = 0, B = 1, C = 2, D = 3, E = 4 */

/* 查找 + 路径压缩：返回 x 所在集合的根，顺手把路径上的结点挂到根上 */

}

}

    printf("  路径：");
    while (parent[x] != x) {
        printf("%c → ", 'A' + x);
        x = parent[x];
    }
    printf("%c（根）\n", 'A' + x);
}

int height(const int parent[]) {
    int h = 0;
    for (int i = 0; i < N; i++) {
        int depth = 0;
        int x = i;
        while (parent[x] != x) {
            x = parent[x];
            depth++;
        }
        if (depth > h) {
            h = depth;
        }
    }
    return h;
}

/* 打印数组 */
void printParent(const int parent[]) {
    printf("parent = {");
    for (int i = 0; i < N; i++) {
        if (i > 0) {
            printf(", ");
        }
        printf("%d", parent[i]);
    }
    printf("}\n");
}

int main(void) {
    int parent[N];
    int rank[N];

    for (int i = 0; i < N; i++) {
        parent[i] = i;
        rank[i] = 0;
    }

    printf("一、朴素合并：只看参数，不看高度\n");
    uniteNaive(parent, 1, 0); /* A 挂到 B 下面 */
    uniteNaive(parent, 2, 1); /* 这一下把 A、B 整棵树挂到了 C 下面 */
    uniteNaive(parent, 3, 2);
    uniteNaive(parent, 4, 3);
    printf("  ");
    printParent(parent);
    printf("  树高：%d\n", height(parent));
    printf("\n");

    printf("二、带路径压缩的 find(A)\n");
    printPath(parent, 0);
    printf("  根是 %c\n", 'A' + find(parent, 0));
    printf("  压缩后：");
    printParent(parent);
    printf("  树高：%d\n", height(parent));
    printf("  再查一次 A：%c（1 步就到）\n", 'A' + find(parent, 0));
```
