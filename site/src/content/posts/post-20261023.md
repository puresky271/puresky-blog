## 没记住形式化证明，只记住形式化推导

哦，很抱歉，我其实没能记住各类自动机之间例如接受语言等价性的严谨证明流程，我大多数时候就只是记住了**如何做题**，可以这么说，拿一个稍微好点的例子来说，我记住了**填表法求一个有限自动机**的商集。

![image](./images/post-20261023/mvl0bdcf-image.png)

（填表法的定义）

这其实可以看成一种**递归**算法，对吧，通过状态链的传递来将已有的初态于终态间的可区分状态一步步推广到全局。我想经过大量的训练之后我应当是已经熟练掌握填表法的各个步骤并能用它来化简基本的有限自动机了。这也让我的考试拿到了相应的分数，看起来没什么不好的，但是：

![image](./images/post-20261023/mvl0i7ks-image.png)

其实像这样，根据自动机状态集合K上的一个等价关系≡的定义进行商集的推到才是讲义中原先推崇的方式，可能这种手段才更接近于**语言和文法的本质**吧。形式化的推导可能能帮你快速建立起对一类题目的熟悉度，但是一遇到考场内外的各种变体，我们就往往会显得束手无策。感觉这就有点像写算法题——有些人能背下KMP算法的核心代码，能把`next`数组顺利的构建出来，但是你让他们去解释KMP的原理呢，让他们去判断何时该用KMP解题呢，那大概就没招了。

然而很不幸的是，我目前也就属于我所批判的人之一，**所以我从来不会觉得自己学会了计算理论**，我甚至连摘取一些所谓低垂果实的能力都没有，又怎么能指望着这门学科以后真的能为我夯实计算机的其他领域的学习呢。

还是看看之后有没有其他的途径继续学习吧，我不想随意鼓吹国外大学的公开课，但是或许这确实是一个很好的选择。

## 一定一定要画图，吗？

研究自动机，没有状态转移图怎么行呢，一个非常经典的例子就是求正则表达式的**图上作业法**。

常规计算：
![image](./images/post-20261023/mvl1dyc2-image.png)

图上作业：
![image](./images/post-20261023/mvl1eiyf-image.png)

图能够直观地展示三类信息。

1. **第一，系统有哪些状态。**圆圈代表状态。你可以直接看到系统有多少种需要区分的情况。

2. **第二，输入会导致什么变化。**箭头代表状态转移。箭头上的字符表示什么输入会触发这次转移。

3. **第三，哪些状态意味着接受。**双圆圈通常表示接受状态。对于有限自动机，只要读完整个输入后处于接受状态，输入字符串就被接受。

这三类信息合起来就完整描述了有限自动机的核心行为。你要是直接去看那个恶心的递归你能瞬间理解求正则表达式中核心的操作吗，好吧我大概是不能。但是这也存在我们先前所言的问题——**过分依赖图形化会让一个人对于计算基础的本质理解退化吗。**

计算机科学里有很多概念在图上看起来相似，数学定义却完全不同。如果你始终通过图形认识这些概念，就可能擅长识别典型图例，却不擅长判断一个新对象是否满足相应的形式化定义。

但不能因此得出图形化越少越好，别画图，直接硬分析最牛的道理。

图形化不仅是辅助工具，它本身也是一种有效的认知工具。

这里有一个例子：并查集的路径压缩，如果只看代码：

```c
int find(int x) {
    if (parent[x] != x) {
        parent[x] = find(parent[x]);
    }
    return parent[x];
}

```

我们可能记住代码，却不明白为什么递归返回后要更新 parent[x]。但如果我们把树画出来观察节点如何直接指向根节点，就更容易理解路径压缩的机制。

同样的，在计算理论中，图形可以帮助你发现状态之间的对称性，等价关系和冗余转移——这些结构往往很难仅靠一串符号直观地看出来。因此我的答案是：**问题不是使用图形好不好，而是你是否拥有脱离图形进行推理的能力。**

## 到底为什么要学计算理论

### 计算理论告诉你计算机不是神

你可以写程序判断一个字符串是否符合某种规则，可以编写如堆排，快排等算法对数字排序。

但是否所有数学问题都能被算法解决？只要有算力，或者说，在这个时代——有token？可计算性理论研究的就是这类问题，它告诉我们**存在一些定义明确的问题，它们不存在能够对所有输入都正确给出答案的通用算法。**

而这便告诉你**计算机能力的边界是什么**， 避免把“没有找到解决方案”误认为“只要足够聪明，总有办法。”

### 它训练你精确定义问题的能力

你必须说清楚输入是什么，输出是什么，允许哪些操作，要求满足什么性质。许多困难的问题在得到清晰定义之前甚至还没有真正开始解决。计算理论的价值就不只是记住自动机的定义，而是让你知道应当提出什么问题，以及哪些保证在理论上根本不可能实现。

### 我认为最重要的一点

**不学这门课，你对计算机的理解永远是别人给的：**你只能使用别人抽象好的东西，无法判断一个抽象好不好，无法在没人给你答案的时候自己推导出答案。

而学了计算理论，你获得的是对这门学科的第一手理解权。

这是“会写代码的人”和“能定义问题的人”的分界线。

## 我学好计算理论了吗

坦白说，没有。

我之所以能在期末考试中发挥正常，靠的是大量的机械记忆，大量的图形化证明——以及半开卷考试的规矩。我一向是一个对数理逻辑的直觉很差的人，靠着拷打ai，然后对着ai的标答照猫画虎才解出了那么几道题，但这不应该是一个学计算机人该有的样子——你现在靠这样的方法熬过了计算理论，之后的编译原理，算法设计能让你这么如法炮制吗，是吧？

所以我在此刻写下这篇文章，一方面是为了给我这段时间的学习留个档，另一方面也是为了警醒我自己——我做的还远远不够好，我不能投机取巧地一直是为了应试来学习计算机的知识，我要做的事情还很多。

**当然，即使迷茫，也要继续前进。**
