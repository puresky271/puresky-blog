**树状数组（Binary Index Tree, BIT）**是一种支持单点修改和区间查询的代码量小的数据结构，它的思想是：**能不能利用整数下标本身的二进制规律，让数组中的每个位置负责一段特定范围，从而用很少的空间实现快速的区间统计？**

1994 年，Peter M. Fenwick 发表论文《A New Data Structure for Cumulative Frequency Tables》，系统介绍了这种结构，并将其用于维护算术编码所需的累计频率表。后来，这种结构以 [Fenwick Tree](https://www.cambridge.org/core/journals/journal-of-functional-programming/article/you-could-have-invented-fenwick-trees/B4628279D4E54229CED97249E96F721D?utm_source=chatgpt.com) 的名字广为人知。

最简单的树状数组支持两种操作：**单点修改**和**区间查询**，时间复杂度均为 $O(\log n)$。

## 题干：力扣307题

给你一个数组 `nums` ，请你完成两类查询。

1. 其中一类查询要求 **更新** 数组 `nums` 下标对应的值

2. 另一类查询要求返回数组 `nums` 中索引 `left` 和索引 `right` 之间（**包含**）的 `nums` 元素的**和**，其中 `left <= right`

实现 `NumArray` 类：

- `NumArray(int[] nums)` 用整数数组 `nums` 初始化对象

- `void update(int index, int val)` 将 `nums[index]` 的值**更新**为 `val`

- `int sumRange(int left, int right)` 返回数组 `nums` 中索引 `left` 和索引 `right` 之间（**包含**）的 `nums` 元素的**和**，即 `nums[left] + nums[left + 1] + ... + nums[right]`

**示例 1：**

```text
输入：
["NumArray", "sumRange", "update", "sumRange"]
[[[1, 3, 5]], [0, 2], [1, 2], [0, 2]]
输出：
[null, 9, null, 8]

解释：
NumArray numArray = new NumArray([1, 3, 5]);
numArray.sumRange(0, 2); // 返回 1 + 3 + 5 = 9
numArray.update(1, 2);   // nums = [1,2,5]
numArray.sumRange(0, 2); // 返回 1 + 2 + 5 = 8
```

**提示：**

- `1 <= nums.length <= 3 * 10^4`
- `-100 <= nums[i] <= 100`
- `0 <= index < nums.length`
- `-100 <= val <= 100`
- `0 <= left <= right < nums.length`
- 调用 `update` 和 `sumRange` 方法次数不大于 `3 * 10^4`

题目来源：[307. 区域和检索 - 数组可修改](https://leetcode.cn/problems/range-sum-query-mutable/)

## 为什么我们需要树状数组

ok，先不管树状数组，**什么是单点修改和区间查询？**

假设我们有一个长度为 $n$ 的数组 $a$，下标从 1 开始。接下来只关心两种操作。

- **单点修改**：只改变数组里某一个位置的值。比如把 $a_3$ 加上 2，或者把 $a_3$ 改成 6。改成某个值也可以看成加上它与原值的差。
- **区间查询**：求一段连续区间 $[l, r]$ 里所有元素的和。比如查询 $[2, 5]$，就是计算 $a_2 + a_3 + a_4 + a_5$。

拿数组 $[3, 1, 4, 1, 5, 9]$ 举例。把 $a_3$ 加上 2 之后，数组变成 $[3, 1, 6, 1, 5, 9]$。这时查询 $[2, 5]$，结果就是 $1 + 6 + 1 + 5 = 13$。

单点修改当然只要改一个位置，时间复杂度是 $O(1)$，但区间求和呢？对于刚才那个可爱的数组，查询 $[2, 5]$ 当然可以笨笨地计算 $a_2 + a_3 + a_4 + a_5$，可如果数组长度来到万级甚至千万级呢？你可能会说这也 ok，因为一次区间求和的时间复杂度是 $O(n)$。

但如果区间查询的次数也来到 $n$ 次呢？总时间复杂度就变成了 $O(n^2)$。力扣 307 的数组长度和操作次数都不超过 $3 \times 10^4$，最坏情况下大约要做 $9 \times 10^8$ 次加法，对于这种数据量肯定会 T。此时如果用树状数组，单次修改和查询都能降到 $O(\log n)$，总复杂度就是 $O(n \log n)$。

## 树状数组的结构和原理

还是用下面图中的数组 $a = [1, 7, 3, 0, 5, 8, 3, 2, 6, 2, 1, 1, 4, 5]$，我们想求它的前 13 项和 $a_1 + a_2 + \cdots + a_{13}$，怎么做？

一种做法当然是从头加到尾，一共要加 13 个数。

但如果我们已经知道**三段区间的和：**

- $A = a_1 + \cdots + a_8 = 29$
- $B = a_9 + \cdots + a_{12} = 10$
- $C = a_{13} = 4$

那么前缀 13 的和就是 $A + B + C = 43$，只需要把 3 个数加起来就好了。

而这三段区间正好对应树状数组里的 `tree[8]`，`tree[12]` 和 `tree[13]`。

这就是树状数组能快速求前缀和的原因：它把前缀 $[1, n]$ 拆成不超过 $O(\log n)$ 段已经存好的区间。查询时只要把这些区间合并起来，复杂度就从 $O(n)$ 降到了 $O(\log n)$。

那说到底，数状数组到底长什么样，它也和我们之前学过的二叉树一样，是一个基于链表的数据结构吗？

不，并不是。**树状数组并不是一棵真正用指针连起来的树，它只是原数组上的一层索引。**每个下标 $i$ 都负责一段以 $i$ 结尾的区间，区间的长度由 $i$ 的二进制表示决定。树状数组的下标从 1 开始，0 只是查询结束时的哨兵。

那问题来了：**怎样知道每个下标负责多长的区间，以及下一步应该跳到哪里？**

答案都藏在 `lowbit` 里。

### lowbit：找到最低位的 1

把一个正整数写成二进制，`lowbit(x)` 就是**最右边那个 1 的位权**。注意它不是这个位的位置，而是这个位代表的数值：

$$
12=(1100)_2 \quad\Rightarrow\quad \operatorname{lowbit}(12)=4
$$

$$
13=(1101)_2 \quad\Rightarrow\quad \operatorname{lowbit}(13)=1
$$

在实际的代码中，我们通常不写循环去找这个位，而是直接使用：

```text
lowbit(x) = x & -x
```

为什么与 `-x` 做按位与就能只留下最低位的 1？**在补码表示中，$-x$ 等于对 $x$ 按位取反后再加 1。**这个加一会把取反结果末尾连续的 1 变成 0，并让最低位的 1 重新出现。更高位则与 $x$ 完全相反。因此，$x$ 和 $-x$ 只有最低位的 1 同时为 1，其余位做按位与后都是 0。

### 节点的管辖范围

`lowbit` 给出了每个节点管辖区间的长度。下标 $i$ 负责一段以 $i$ 结尾、长度为 $\operatorname{lowbit}(i)$ 的区间：

$$
\operatorname{tree}[i]=\sum_{k=i-\operatorname{lowbit}(i)+1}^{i}a_k
$$

换成区间写法，就是 $[i-\operatorname{lowbit}(i)+1,i]$。

它的右端点永远是当前下标 $i$，左端点则由 `lowbit` 决定。例如 `tree[12]` 的长度是 4，负责 $[12-4+1,12]=[9,12]$，`tree[13]` 的长度是 1，只负责 $[13,13]$。

> [!TIP]
> 这里对于区间的定义，给你一个我自己的直观理解：`[最左边的兄弟下标, 自己]`

### 查询前缀和：向左拼区间

有了树状数组，我们在求 $[1,i]$ 的和时就不需要逐个读取原数组了。当前 `tree[i]` 已经保存了区间 $[i-\operatorname{lowbit}(i)+1,i]$，所以可以直接把它当作一整块取走，然后继续求左边剩余的前缀：

1. 把 `tree[i]` 加进 `sum`。
2. 执行 `i -= i & -i`，跳过刚刚累加的区间。
3. 重复以上过程，直到 $i=0$。

用一句话来描述每一步，就是：**累加当前区间，然后跳过它。**

**第一步：站在下标 13，取走 `[13,13]`。**

当前还缺整个前缀 $[1,13]$。`tree[13]` 只管辖 $a_{13}$，所以先得到：

$$
\operatorname{sum}=0+4=4
$$

现在已经覆盖 $[13,13]$，左边还缺 $[1,12]$。由于 $\operatorname{lowbit}(13)=1$，下一下标就是 $13-1=12$。

**第二步：跳到下标 12，取走 `[9,12]`。**

`tree[12]=10` 一次保存了 $a_9+a_{10}+a_{11}+a_{12}$，不需要再分别读取这四个数。累加后：

$$
\operatorname{sum}=4+10=14
$$

现在已经覆盖 $[9,13]$，左边还缺 $[1,8]$。由于 $\operatorname{lowbit}(12)=4$，下一下标就是 $12-4=8$。

**第三步：跳到下标 8，取走 `[1,8]`。**

`tree[8]=29` 正好管辖剩余的整个前缀，因此：

$$
\operatorname{sum}=14+29=43
$$

最后 $\operatorname{lowbit}(8)=8$，下标变成 $8-8=0$，查询结束。三段区间无缝拼成 $[1,13]$，最终结果就是：

$$
\operatorname{query}(13)=\operatorname{tree}[13]+\operatorname{tree}[12]+\operatorname{tree}[8]=4+10+29=43
$$

对应代码为：

```text

        sum += tree[i]
        i -= i & -i
    return sum
```

### 单点更新：向上寻找覆盖区间

更新与查询的方向相反。假设执行 `a[3] += 2`，只改原数组还不够，因为 $a_3$ 同时属于 `tree[3]` 的 $[3,3]$、`tree[4]` 的 $[1,4]$ 和 `tree[8]` 的 $[1,8]$。这些区间和都必须增加 2，之后的查询才能读到正确结果。

更新时先修改当前 `tree[i]`，再执行 `i += i & -i`，寻找下一个包含该元素的更大区间。超出数组长度 $n$ 时停止：

$$
\begin{aligned}
3+\operatorname{lowbit}(3)&=3+1=4\\
4+\operatorname{lowbit}(4)&=4+4=8\\
8+\operatorname{lowbit}(8)&=8+8=16>14
\end{aligned}
$$

因此更新路径是 $3\to4\to8$，依次得到 `tree[3] = 5`、`tree[4] = 13`、`tree[8] = 31`，而 16 越界，不再更新。动画中的“已改”节点就是所有受到这次单点修改影响的区间：

:::animation fenwick-update
index: 3
delta: 2
:::

对应代码为：

```text
add(i, delta):
    while i <= n:
        tree[i] += delta
        i += i & -i
```

查询时减去 `lowbit`，把前缀拆成若干已有区间。更新时加上 `lowbit`，把所有覆盖修改位置的区间同步修正。两条路径都不会超过二进制位数，因此单次查询和单点更新的时间复杂度都是 $O(\log n)$。

## 建树与基本操作

下面的通用实现把建树，单点增量更新 `add` 和前缀和查询 `query` 放在一起。构造函数从全 0 的 `tree` 开始，依次把原数组的每项加入对应位置，建树复杂度为 $O(n\log n)$，空间复杂度为 $O(n)$。

:::tabs
```cpp
#include <vector>
using namespace std;

class FenwickTree {
private:
    int n;
    vector<int> tree;

    int lowbit(int x) const {
        return x & -x;
    }

public:
    explicit FenwickTree(const vector<int>& nums)
        : n(static_cast<int>(nums.size())), tree(nums.size() + 1, 0) {
        for (int i = 0; i < n; ++i) {
            add(i + 1, nums[i]);
        }
    }

    // 让原数组下标 index 对应的值增加 delta
    void add(int index, int delta) {
        while (index <= n) {
            tree[index] += delta;
            index += lowbit(index);
        }
    }

    // 返回原数组前缀 [1, index] 的和
    int query(int index) const {
        int sum = 0;
        while (index > 0) {
            sum += tree[index];
            index -= lowbit(index);
        }
        return sum;
    }
};
```

## 力扣 307：三语言完整代码

力扣 307 的 `update(index, val)` 是**赋值**，而树状数组的 `add` 接收的是**增量**。因此需要额外保存原数组，先计算 `delta = val - nums[index]`，再执行 `add(index + 1, delta)`。这里的 `+1` 是在把力扣的 0 基下标转换成树状数组的 1 基下标。

区间和则由两个前缀和相减得到：`sumRange(left, right) = query(right + 1) - query(left)`。

:::tabs
```cpp
#include <vector>
using namespace std;

class NumArray {
private:
    int n;
    vector<int> nums;
    vector<int> tree;

    int lowbit(int x) const {
        return x & -x;
    }

    void add(int index, int delta) {
        while (index <= n) {
            tree[index] += delta;
            index += lowbit(index);
        }
    }

    int query(int index) const {
        int sum = 0;
        while (index > 0) {
            sum += tree[index];
            index -= lowbit(index);
        }
        return sum;
    }

public:
    explicit NumArray(vector<int>& nums)
        : n(static_cast<int>(nums.size())), nums(nums), tree(nums.size() + 1, 0) {
        for (int i = 0; i < n; ++i) {
            add(i + 1, nums[i]);
        }
    }

    void update(int index, int val) {
        int delta = val - nums[index];
        nums[index] = val;
        add(index + 1, delta);
    }

    int sumRange(int left, int right) const {
        return query(right + 1) - query(left);
    }
};
```

## 区间加与区间和：差分数组

前面支持的是单点修改。如果要把 $[l,r]$ 里的每个元素都加上 $v$，同时还能查询任意区间的和，可以先引入**差分数组**：

$$
d_1=a_1,\qquad d_i=a_i-a_{i-1}\quad(i>1)
$$

差分的前缀和就是原数组，即 $a_i=\sum_{k=1}^{i}d_k$。因此给原数组的 $[l,r]$ 整体加上 $v$，在差分数组里只需要修改两个位置：

$$
d_l\mathrel{+}=v,\qquad d_{r+1}\mathrel{-}=v
$$

左端点 $l$ 让后面的前缀和都增加 $v$，右端点之后的 $r+1$ 再把多出来的部分抵消。下面用一个全 0 数组执行 $[3,6]$ 加 5，可以看到差分只改动 $d_3$ 和 $d_7$，还原后的原数组却正好改变了连续四项。

不过，**只有差分还不够求区间和**。把前缀和展开，可以发现每个差分项 $d_k$ 会出现 $i-k+1$ 次：

$$
\begin{aligned}
\operatorname{prefix}(i)
&=\sum_{j=1}^{i}a_j
=\sum_{k=1}^{i}(i-k+1)d_k\\
&=(i+1)\sum_{k=1}^{i}d_k-\sum_{k=1}^{i}k\,d_k
\end{aligned}
$$

例如求 `prefix(6)` 时，$d_1$ 的权重是 6，$d_2$ 的权重是 5，直到 $d_6$ 的权重变成 1。刚才的 $d_3=5$ 因而会贡献 $5\times4=20$，而不在前缀内的 $d_7$ 不参与计算。

因此需要两棵树状数组：第一棵维护 $d_k$ 的前缀和，第二棵维护 $k\,d_k$ 的前缀和。执行区间加 $[l,r]\mathrel{+}=v$ 时两棵树都在 $l$ 和 $r+1$ 更新，但第二棵使用的增量分别是 $l\,v$ 和 $-(r+1)v$。

查询时先代入上面的公式求 `prefix(i)`，再做一次前缀和相减：

$$
\operatorname{sum}(l,r)=\operatorname{prefix}(r)-\operatorname{prefix}(l-1)
$$

这样区间加和区间和都只需要常数次树状数组操作，时间复杂度仍为 $O(\log n)$。

---
树状数组固然是一个令人惊叹的数据结构，但如果题目涉及**区间修改，区间最值，复杂区间信息合并，或者不同区间需要维护不同的状态**，这时候单纯的树状数组就显得有点力不从心了。

于是，我们就得在下一节请出另一个和它非常相像的数据结构：**线段树**。
