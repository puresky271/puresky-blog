红黑树是一种自平衡的二叉查找树，是一种高效的查找树。它是由 Rudolf Bayer 于1972年发明，在当时被称为对称二叉 B 树(symmetric binary B-trees)。后来，在1978年被 Leo J. Guibas 和 Robert Sedgewick 修改为如今的红黑树。

在二叉树的相关章节中，我们曾经提及过平衡二叉树这个概念，平衡二叉树最大的作用就是查找。以AVL树为例，它的查找，插入和删除在平均和最坏情况下都是$$O(logn)$$。但如果在AVL树中插入或删除节点后，使得高度之差大于1。此时AVL树的平衡状态就被破坏，它就不再是一棵二叉树，那么为了让它重新维持在一个平衡状态，就需要对其进行**旋转处理**。但创建一颗平衡二叉树的成本不小，于是就有人出了红黑树的理论，红黑树在业界应用很广泛，比如 Java  中的 `TreeMap`，JDK 1.8 中的 `HashMap`，还有 C++ STL 中的 `map` 均是基于红黑树结构实现的。

## 你为什么会需要红黑树——AVL树的缺点

先来看这个总表：

| 比较维度 | 红黑树 | AVL 树 |
| --- | --- | --- |
| 平衡要求 | 相对宽松 | 更严格 |
| 最坏查找 | $O(\log n)$ | $O(\log n)$ |
| 最坏插入 | $O(\log n)$ | $O(\log n)$ |
| 最坏删除 | $O(\log n)$ | $O(\log n)$ |
| 查找性能 | 通常略逊一些 | 通常更好 |
| 更新时的平衡维护 | 通常更有优势 | 可能需要更多调整 |
| 典型用途 | 通用有序映射和集合 | 查找密集型场景 |

AVL 树的定义，平衡因子，左右旋以及维护代价，前面 AVL 那篇已经讲完了，这里直接拿结论说事：AVL 树把平衡卡得太死，任何节点的高度差都不能超过 1，插入和删除之后往往要一路回溯检查，删除时还可能连锁旋转。红黑树的平衡条件松得多，它不追求每个节点都严格平衡，只要求从根到叶子的最长路径不超过最短路径的两倍，换来的是更新时更少的旋转和更便宜的调整。

所以接下来要做的，是把红黑树这套“用颜色换维护成本”的规则讲清楚。
