我们可能一上来就直接讲红黑树，但是我们一上来就直接讲红黑树不太可能。

**红黑树是一种自平衡的二叉查找树**，是一种高效的查找树，所以如果我们需要把红黑树讲明白，那么我们就得先搞清楚二叉查找树以及平衡二叉树的相关概念。所幸关于二叉树本身我们之前已经有较为清楚的讲解，于是乎，为了见到红黑树这个关底boss，让我们按照这个顺序一步步推进：

```text
AVL → B 树 → B+ 树 → 红黑树
```

本文即为红黑树的前置文章的第一节：什么是AVL树，我们将在这一节中借助AVL树建立对于**“维护平衡”**的基本概念。

## 二叉查找树是什么

**二叉查找树**（Binary Search Tree，简称 **BST**），也称**二叉搜索树**或**二叉排序树**，是一种特殊的二叉树数据结构。

### 1.核心定义和性质：

对于树中的任意一个节点 $X$：
* **左子树**上所有节点的值，都**小于**节点 $X$ 的值
* **右子树**上所有节点的值，都**大于**节点 $X$ 的值
* 节点 $X$ 的左子树和右子树本身也必须是二叉查找树

> [!NOTE]
> 通常情况下树中不允许出现重复值的节点。若允许重复，可统一约定放在左子树或右子树

### 2. 两个重要特点：
* **中序遍历是有序的**：对二叉查找树进行**中序遍历**（左子树 $\to$ 根节点 $\to$ 右子树），遍历结果正好是一个**升序排列**的序列。
* **高效的查找与操作**：由于树的有序性，在进行查找，插入或删除时，每次只需与当前节点比较大小，就能排除一半的子树（类似于二分查找）：
  * **平均时间复杂度**：$O(\log n)$。

### 3. 局限与演进
* **退化问题**：如果插入的数据本身是有序的（例如依次插入 1, 2, 3, 4, 5），BST 可能会退化成一条类似链表的结构，此时查找和操作的时间复杂度会退化为 **$O(n)$**。
* **平衡树的诞生**：为了解决这种极端情况下的性能退化，计算机科学家在 BST 的基础上发展出了**平衡二叉树**（如本节要讲的AVL，和我们的终极目标：红黑树），它们通过在插入或删除时进行旋转操作，确保树的高度始终维持在 $O(\log n)$ 级别。

## 那有谁能告诉我什么是AVL树吗

AVL 是大学教授 G.M. Adelson-Velsky 和 E.M. Landis 名称的缩写，他们提出的平衡二叉树的概念，为了纪念他们，将 平衡二叉树 称为 AVL树。

AVL树本质上就是一颗二叉查找树，但是AVL树相较于一般的二叉查找树而言有着一个核心的特点：**在AVL树中，任何节点的两个子树的高度最大差别为 1（或者它是一颗空树）。**

把这句话拆成能直接照着写代码的条件：

- 它首先是一棵二叉查找树。
- 对每个结点，左右子树的高度差（平衡因子）只能取 −1，0，1 三个值之一。
- 左右子树本身也必须是一棵 AVL 树。

## 怎么计算平衡因子

前面判断一棵树是不是 AVL 树用的都是“左右子树高度差”，这个所谓的差值有个正式名字：**平衡因子**（Balance Factor，BF），定义是

$$
BF = h_L - h_R
$$

$h_L$ 和 $h_R$ 分别是这个节点左子树和右子树的高度。所以想算平衡因子得先会算树高：**空子树的高度记 0，叶子节点记 1，其余节点的高度等于左右子树中较高的那个再加 1。**从下往上一层一层推即可。

## AVL树的作用

AVL 树最核心的作用就是把树高稳定地压在 $O(\log n)$ 这一档，让查找，插入和删除都保持在对数级别。

## 左旋与右旋

既然我们一直在说AVL是通过旋转来进行调平的，那到底什么是旋转呢？这里的标题是“左旋与右旋”，这和我高中学过的手性异构有关系吗？

> [!NOTE]
> **手性异构（Chiral Isomerism）**是一种非常特殊的空间立体异构现象。
简单来说，如果两个分子的化学式和连接顺序完全相同，互为镜像，但无论在空间中如何旋转都无法完全重合，这种现象就叫做手性异构。

哦不，我们不是在研究有机化学，这里的“旋转”其实很简单——平衡因子超出 ±1 时，我们得把树拧回来。AVL 树调平衡的动作只有两个：**右旋**和**左旋**。

## 插入节点

插入分两步：先按二叉查找树的规则把新结点挂到叶子位置，再从插入点向上回溯，更新高度，计算平衡因子。

某个祖先的平衡因子一旦变成 ±2，就对它旋转一次。可能是下面四种之一：

- LL 型：左孩子的左子树太高，对失衡结点右旋
- RR 型：右孩子的右子树太高，对失衡结点左旋
- LR 型：左孩子的右子树太高，先对左孩子左旋，再对失衡结点右旋
- RL 型：右孩子的左子树太高，先对右孩子右旋，再对失衡结点左旋

插入只需要调整一次。旋转之后这棵子树的高度回到插入前的值，再往上的祖先不会再失衡，所以插入的旋转次数是一个常数。

## 删除节点

删除分三种情况：

- 叶子结点：直接删掉
- 只有一个孩子：用这个孩子顶替它的位置
- 两个孩子：用中序后继（右子树里最小的结点）替换它的值，再把这个后继结点删掉

删完同样从删除位置向上回溯。和插入不一样的是，删除引起的旋转可能一路连锁，最坏要转 $O(\log n)$ 次，不过整体复杂度仍然是 $O(\log n)$。

## 代码实现

三份代码是同一套 AVL 树，覆盖插入，删除和四种旋转（LL，LR，RR，RL），注释标出了每个函数对应哪种失衡：

:::tabs
```c
#include <stdlib.h>

typedef struct Node {
    int key;
    int height;
    struct Node *left;
    struct Node *right;
} Node;

int height(Node *n) {
    return n ? n->height : 0;
}

int max(int a, int b) {
    return a > b ? a : b;
}

void update(Node *n) {
    n->height = max(height(n->left), height(n->right)) + 1;
}

int balance_factor(Node *n) {
    return height(n->left) - height(n->right);
}

// LL 型：左孩子的左子树太高，对 a 右旋

        p->left = p->right = NULL;
```

```java
// AVL 树：插入和删除，包含 LL、LR、RR、RL 四种旋转
public class AvlTree {

    static class Node {
        int key;
        int height = 1;
        Node left;
        Node right;

        Node(int key) {
            this.key = key;
        }
    }

    private int height(Node n) {
        return n == null ? 0 : n.height;
    }

    private void update(Node n) {
        n.height = Math.max(height(n.left), height(n.right)) + 1;
    }

    private int balanceFactor(Node n) {
        return height(n.left) - height(n.right);
    }

    // LL 型：左孩子的左子树太高，对 a 右旋
    private Node rotateRight(Node a) {
        Node b = a.left;
        a.left = b.right;
        b.right = a;
        update(a);
        update(b);
        return b;
    }

    // RR 型：右孩子的右子树太高，对 a 左旋
    private Node rotateLeft(Node a) {
        Node b = a.right;
        a.right = b.left;
        b.left = a;
        update(a);
        update(b);
        return b;
    }

    // LR 型：先对左孩子左旋，把折角扳成 LL，再对 a 右旋
    private Node rotateLR(Node a) {
        a.left = rotateLeft(a.left);
        return rotateRight(a);
    }

    // RL 型：先对右孩子右旋，把折角扳成 RR，再对 a 左旋
    private Node rotateRL(Node a) {
        a.right = rotateRight(a.right);
        return rotateLeft(a);
    }

    // 当前子树失衡就按类型旋转，返回新的子树根
    private Node rebalance(Node n) {
        update(n);
        int bf = balanceFactor(n);
        if (bf > 1) {
            return balanceFactor(n.left) < 0 ? rotateLR(n) : rotateRight(n);
        }
        if (bf < -1) {
            return balanceFactor(n.right) > 0 ? rotateRL(n) : rotateLeft(n);
        }
        return n;
    }

    // 插入：先按二叉查找树规则插到叶子位置，再逐层回溯平衡
    public Node insert(Node n, int key) {
        if (n == null) {
            return new Node(key);
        }
        if (key < n.key) {
            n.left = insert(n.left, key);
        } else if (key > n.key) {
            n.right = insert(n.right, key);
        } else {
            return n;
        }
        return rebalance(n);
    }

    private Node minNode(Node n) {
        while (n.left != null) {
            n = n.left;
        }
        return n;
    }

    // 删除：处理叶子、单孩子、双孩子三种情况，再逐层回溯平衡
    public Node delete(Node n, int key) {
        if (n == null) {
            return null;
        }
        if (key < n.key) {
            n.left = delete(n.left, key);
        } else if (key > n.key) {
            n.right = delete(n.right, key);
        } else {
            if (n.left == null) {
                return n.right;
            }
            if (n.right == null) {
                return n.left;
            }
            Node succ = minNode(n.right);   // 双孩子：用中序后继替换
            n.key = succ.key;
            n.right = delete(n.right, succ.key);
        }
        return rebalance(n);
    }
}
```

## 为什么最后还是用红黑树

目前为止看上去一切正常，那为什么我们最后还是放弃了AVL转而去研发了红黑树呢？

原因大概有两个：
- AVL 树插入后，如果某个结点失衡，就需要更新高度信息，并通过旋转恢复平衡。红黑树则通过重新着色和旋转恢复红黑性质
- AVL 树删除结点后，可能导致多个祖先结点依次失衡。修复可能沿着从删除位置到根结点的路径持续进行，最坏情况下需要 $$O(log n)$$次旋转。红黑树删除后也可能需要沿路径修复黑高，但它的删除修复过程最多需要 3 次旋转，其他工作主要由重新着色和沿路径调整完成。

2. 这次左旋让 10 这棵子树的高度从 3 掉到 2。再往上回到 25，它原来的平衡因子也是 −1，左边矮了一层之后变成 −2，同样失衡。再对 25 做一次左旋，45 顶上来成为新的根。

这棵只有 13 个结点的树**删一片叶子就转了两次。**那如果树再高几层的话，同样的连锁还会继续往上，最坏情况要沿着路径一路转上去，旋转次数是 $O(\log n)$ 级别，这可不是一个定值。对比一下红黑树：插入最多 2 次旋转，删除最多 3 次，其余调整只需要重新染色这种不碰指针的便宜操作，所以结点再多，它的旋转次数也有一个固定上界。

**下一节为什么先讲 B 树**

那红黑树这么强了，给它了呗，我们直接去讲红黑树？

确实，你可能想直接翻到红黑树去看它的五条规则，**但红黑树有一个麻烦：规则看起来像凭空规定的。**根必须是黑的，红结点不能相邻，从根到每个空指针经过的黑结点数量必须相同，然后还要配一整套插入删除的修复流程。如果直接硬讲的话，我们会很难想明白这些规则是谁想出来的，最后就只能变成会做题但是不了解红黑树本质的人，那可不好。

其实红黑树是 2-3-4 树的二叉表示。2-3-4 树是一种**四阶 B 树**，一个节点里放 1 到 3 个键，孩子有 2 到 4 个。B 树允许节点里塞多个键，这正是红黑树颜色的来源：**把节点里多出来的键拆成红色结点挂到黑色结点旁边，红色和黑色描述的就是这种拆分关系。**

所以我们要先看懂 B 树怎么在节点里塞多个键，怎么分裂和合并，再回来看红黑树。而且 B 树和 B+ 树本身也值得单独讲，它们是磁盘索引的基础，B+ 树几乎是数据库索引的标准答案。总而言之，接下来的顺序是 B 树，然后 B+ 树，最后才回到红黑树。
