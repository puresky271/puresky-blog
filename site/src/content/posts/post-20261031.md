我们之前已经完整的经历过了一次遍历二叉树的折磨，我们在对一棵二叉树做某种次序遍历的时候可以得到某一个我们所指定的节点的前驱/后继的关系，但问题在于，要想知道这一信息我们就必须遍历一次。以后每次需要知道时都必须遍历一次。有点麻烦对吧？为什么不考虑**在创建时就记住这些前驱和后继**呢？

我们发明线索二叉树（Threaded Binary Tree），本质上是为了解决一个问题：

**二叉树中存在大量空指针，而这些空指针能不能被利用起来，让我们更方便地进行遍历**？

## 一、普通二叉树存在什么问题

在普通二叉树中，每个结点都有两个指针域：

- `left`：指向左孩子。
- `right`：指向右孩子。

这两个指针域是结点结构里固定分配好的部分，不管结点到底有没有孩子。叶子结点一个孩子也没有的话它的两个指针域就只能空着，白白占着两格内存。

图里一共有 6 个结点，所以指针域有 12 个。而这棵树只有 5 条分支，填上了孩子地址的指针只有 5 个，**剩下的 7 个全是空指针。**

让我们把这件事放大到任意一棵二叉树。假设一棵二叉树有 $n$ 个结点，那么：

- 每个结点有两个指针域，总共 $2n$ 个指针域。
- 一棵有 $n$ 个结点的二叉树，实际只有 $n-1$ 条分支。

每条分支占用父结点的一个指针，所以被用掉的指针正好是 $n-1$ 个。因此，空指针域的数量为：

$$
2n-(n-1)=n+1
$$

这个结果和树的形状无关，也和结点怎么排列无关。**一棵有 $n$ 个结点的二叉树，永远有 $n+1$ 个指针是空的**，差不多占了全部指针域的一半。

凭什么白白浪费这些空间呢？既然空指针这么多，那就有 $n+1$ 次机会把它们捡起来用。这也就是线索二叉树要做的事。

## 二、线索二叉树

线索二叉树具体的规定是：**某个结点的左指针为空时，让它指向这个线性序列中该结点的前驱结点。某个结点的右指针为空时，让它指向这个线性序列中该结点的后继结点。**

这里的线性序列就是遍历得到的结点序列，中序线索二叉树对应的就是中序序列。指向了前驱或者后继的指针，我们叫它**线索**。

但指针域里存的东西到底是指向孩子还是指向线索呢？这件事光看指针本身是分不出来的。所以每个结点要多加两个标志位：

- `ltag = 0`：`lchild` 指向左孩子结点。
- `ltag = 1`：`lchild` 指向前驱结点。
- `rtag = 0`：`rchild` 指向右孩子结点。
- `rtag = 1`：`rchild` 指向后继结点。

加了标志位之后，每个结点的存储结构从三个域变成了五个域：

| ltag | lchild | data | rchild | rtag |
| :--- | :--- | :--- | :--- | :--- |
| 左标志 | 左指针 | 数据 | 右指针 | 右标志 |

还有一个细节。就像我们为链表创建哨兵节点一样，**为了让创建线索二叉树的算法写起来方便，通常在线索二叉树里再加一个头结点。**

头结点的 data 域为空。**它的 lchild 指向没有线索时的根结点**，也就是原本二叉树的根结点，所以 ltag 为 0。**rchild 指向按某种方式遍历这棵二叉树得到的最后一个结点**，所以 rtag 为 1。

这样一来线索二叉树里就没有空指针域了，第一个结点的前驱和最后一个结点的后继原本无处可指，现在都指向了头结点，头结点自己的两个指针也各有归宿。

这棵树的中序序列是 D，G，B，A，E，C，F。给出一些节点的例子：

- 根结点 A 的左右指针都指向孩子，所以 ltag 和 rtag 都是 0。
- B 的右指针本来是空的，现在指向中序后继 A，rtag 就变成 1。它的左指针仍然指向孩子 D，ltag 是 0。
- D 是中序序列的第一个结点，左指针空着，就指向前驱，也就是头结点。它的右指针指向孩子 G，所以 rtag 是 0。
- G 的左右指针都空，分别指向前驱 D 和后继 B，两个标志位都是 1。
- E 的左指针空着，指向前驱 A，右指针也空着，指向后继 C，两个标志位都是 1。
- C 的左右指针分别指向孩子 E 和 F，两个标志位都是 0。
- F 是中序序列的最后一个结点，右指针空着，指向后继，也就是头结点，rtag 是 1。

线索化之后，找前驱和后继都变成了一次指针跳转，不再需要在树里上下摸索。这就是线索二叉树的意义，代价是每个结点多了两个标志位。

## 三、设计线索二叉树

### 结点定义

五个域落到代码里就是一个结构体（Java 里是类）。`ltag` 和 `rtag` 的初值取 0，表示两个指针暂时都指向孩子。

:::tabs
```c
// 线索二叉树结点
typedef struct ThreadNode {
    char data;                      // 数据域
    struct ThreadNode *lchild;      // 左孩子或前驱
    struct ThreadNode *rchild;      // 右孩子或后继
    int ltag;                       // 0：lchild 指向左孩子，1：lchild 指向前驱
    int rtag;                       // 0：rchild 指向右孩子，1：rchild 指向后继
} ThreadNode, *ThreadTree;
```

```cpp
// 线索二叉树结点
struct ThreadNode {
    char data;                      // 数据域
    ThreadNode* lchild = nullptr;   // 左孩子或前驱
    ThreadNode* rchild = nullptr;   // 右孩子或后继
    int ltag = 0;                   // 0：lchild 指向左孩子，1：lchild 指向前驱
    int rtag = 0;                   // 0：rchild 指向右孩子，1：rchild 指向后继
};
```

```java
// 线索二叉树结点
class ThreadNode {
    char data;              // 数据域
    ThreadNode lchild;      // 左孩子或前驱
    ThreadNode rchild;      // 右孩子或后继
    int ltag = 0;           // 0：lchild 指向左孩子，1：lchild 指向前驱
    int rtag = 0;           // 0：rchild 指向右孩子，1：rchild 指向后继

    ThreadNode(char data) {
        this.data = data;
    }
}
```
:::

**线索化不是另建一棵树，而是在一次遍历里顺手把空指针改掉。树还是原来那棵树，只是那些原本空着的指针换成了指向前驱或者后继的线索，结点上的两个标志位跟着一起改。**

我们用一个指针 `pre` 记住刚刚访问过的结点。遍历走到 `p` 的时候，依次做三件事：

- `p` 的左指针为空，就把它改成指向 `pre`，`ltag` 置 1，这是一条前驱线索。
- `pre` 的右指针为空，就把它改成指向 `p`，`rtag` 置 1，这是一条后继线索。
- 最后把 `pre` 挪到 `p`，也就是 `pre = p`。

“访问”这一步放在什么位置由遍历次序决定，同一棵树按中序，先序，后序线索化，会得到三棵不同的线索树。

下面三节的动画用的都是前面那棵 7 个结点的树，你可以看到`pre` 在结点之间跳动，跳到位的话就有一条虚线从原来空着的指针里长出来。

中序和先序还可以在最外面再套一个头结点，把首尾两端也收进去。

### 中序线索二叉树

中序线索化的递归次序和普通中序遍历完全一样：左子树，访问，右子树，`pre` 一直走在 `p` 后面记下刚刚访问过的结点。

 `pre`经过结点的顺序正好就是中序序列 D，G，B，A，E，C，F。虚线从哪个空指针里长出来，那个指针原来就是空的，线索就是在这儿补上去的。

:::animation thread-build
order: inorder
:::

整棵树走完一共生成 9 条线索。第一个结点的左指针和最后一个结点的右指针都连到了头结点上，而我们再让头结点的 rchild 指向最后一个结点，这样首尾就接上了。

:::tabs
```c
// 中序线索化：左子树，访问结点，右子树
void inThread(ThreadTree p) {
    if (!p) return;
    inThread(p->lchild);                       // 1. 左子树
    if (!p->lchild) {                          // 2. 左指针空，建成前驱线索
        p->lchild = pre;
        p->ltag = 1;
    }
    if (pre && !pre->rchild) {                 // 3. pre 的右指针空，建成后继线索
        pre->rchild = p;
        pre->rtag = 1;
    }
    pre = p;                                   // 4. pre 后移
    inThread(p->rchild);                       // 5. 右子树
}
```


```java
        p.ltag = 1;
    }

        pre.rchild = p;
        pre.rtag = 1;

}
```

### 先序线索二叉树

先序线索化的递归次序是访问，左子树，右子树。

改指针还是那三条规则，但这里多了两个必须判断的地方：

`p` 的左指针可能在访问时刚被改成前驱线索，递归左子树之前要先看 `ltag`，如果为 1 就说明那不是孩子，不能再往下走。右指针更隐蔽，递归左子树的时候第一个被访问的就是左孩子，这时 `pre` 还是 `p`，如果 `p` 的右指针为空，它当场就被写成指向左孩子的后继线索。所以递归右子树之前同样要看 `rtag`，示例树里 B 的右指针就是在访问 D 时变成指向 D 的线索的，如果漏掉着两个判断的任意一个的话，递归就会绕回已经访问过的结点。整棵树走完同样生成 9 条线索。

:::animation thread-build
order: preorder
:::

:::tabs
```c
// 先序线索化：访问结点，再递归
void preThread(ThreadTree p) {
    if (!p) return;
    if (!p->lchild) { p->lchild = pre; p->ltag = 1; }                 // 左指针空，建成前驱线索
    if (pre && !pre->rchild) { pre->rchild = p; pre->rtag = 1; }      // pre 的右指针空，建成后继线索
    pre = p;
    if (p->ltag == 0) preThread(p->lchild);    // 左指针可能刚被改成线索，判断后再递归
    if (p->rtag == 0) preThread(p->rchild);    // 右指针也可能在左子树里被改成线索
}
```


### 后序线索二叉树

后序的递归次序是左子树，右子树，访问，指针要等回溯的时候才改。先一路递归到叶子再从下面往上处理，所以不存在先序那种改完指针又照着走的问题。

后序序列是 G，D，B，E，F，C，A。第一个结点 G 没有前驱，`pre` 还是空的，它的左指针就一直空着。最后一个结点是根 A，A 的右指针还指着真正的右孩子 C，不能像中序那样指回头结点，**所以后序线索树一般不加头结点。**

:::animation thread-build
order: postorder
:::

**后序线索树找后继得先知道双亲，实际很少拿它做遍历。**整棵树走完一共生成 7 条线索。

:::tabs
```c
// 后序线索化：先递归，最后处理结点。后序不带头结点，调用前 pre 置空
void postThread(ThreadTree p) {
    if (!p) return;
    postThread(p->lchild);
    postThread(p->rchild);
    if (!p->lchild) { p->lchild = pre; p->ltag = 1; }                 // 左指针空，建成前驱线索
    if (pre && !pre->rchild) { pre->rchild = p; pre->rtag = 1; }      // pre 的右指针空，建成后继线索
    pre = p;
}
```

### 带头结点的收口

中序和先序都可以套一个头结点，把第一个结点的前驱和最后一个结点的后继也收进来。后序不行，上一节已经说过原因。

头结点的 `lchild` 指向根，`ltag` 为 0，`rtag` 为 1，`rchild` 先指向自己，空树时两个指针都指回自己。线索化之前把 `pre` 置成头结点，第一个结点没有前驱时，它的左指针就直接连到头结点上。线索化结束以后，先把最后一个结点的右指针指回头结点，再让 `head.rchild` 指向最后一个结点，首尾两端就都接上了（中序那一节的动画最后两条虚线就是这两步）。

:::tabs
```c
ThreadNode *pre = NULL;   // 刚访问过的结点

// 中序和先序共用这个骨架：线索化函数换成 inThread 或 preThread
ThreadTree buildThreadTree(ThreadTree T) {
    ThreadTree head = (ThreadTree)malloc(sizeof(ThreadNode));
    head->ltag = 0;        // lchild 当孩子指针用
    head->rtag = 1;        // rchild 当线索用
    head->rchild = head;   // 空树时右线索指向自己
    if (!T) {
        head->lchild = head;
        return head;
    }
    head->lchild = T;      // 头结点的左孩子指向根
    pre = head;            // 第一个结点的前驱是头结点
    inThread(T);           // 先序就换成 preThread(T)
    pre->rchild = head;    // 最后一个结点的右线索指回头结点
    pre->rtag = 1;
    head->rchild = pre;    // 头结点的右线索指向最后一个结点
    return head;
}
```

## 四、遍历线索二叉树

还记得我们当初为什么要发明线索树二叉树吗？没错，就是为了方便我们的遍历操作。

**线索二叉树的遍历不用递归也不用栈，顺着线索就能把一个序列走完。**

### 遍历思想上的共同点

三种线索二叉树都遵循一个基本思路：

1. 找到遍历序列中的第一个结点。
2. 根据当前结点的孩子指针或线索，寻找下一个结点。
3. 不断重复，直到遍历结束。

这里需要注意：寻找后继的具体算法并不完全相同。尤其是后序线索二叉树，寻找后继时可能要借助父结点的信息，因此不能简单地套用中序线索二叉树的算法，后序那一节会反过来，从最后一个结点出发顺着前驱倒着走。

三种遍历都是 $O(n)$，每条边和每条线索最多走一次。先序和中序只靠一个 `p` 指针往前挪，后序要借一个栈把收集到的顺序倒过来。

### 中序线索二叉树的遍历

中序线索树找后继只有两种情况。`rtag == 1` 时 `rchild` 直接就是后继，`rtag == 0` 时后继藏在右子树里，去右子树一路往左下走到底就是了。

遍历从根出发，先往左下走到第一个结点 D，你会发现这就是中序序列的开头。带头的线索树里第一个结点的前驱是头结点，最后一个结点的后继也是头结点，所以一路走一路求后继，重新踩回 `head` 就说明走完了。

:::animation thread-traverse
order: inorder
:::

走出来的序列是 D，G，B，A，E，C，F，和递归版中序遍历得到的结果一致。整个过程 `p` 只沿着指针往前挪，没有回头路。

:::tabs
```c
// 从 p 出发一路向左下，找到 p 子树里中序的第一个结点
ThreadTree FirstNode(ThreadTree p) {
    while (p->ltag == 0) p = p->lchild;
    return p;
}

// p 的中序后继
ThreadTree NextNode(ThreadTree p) {
    if (p->rtag == 0) return FirstNode(p->rchild);   // 右子树里最左下的结点
    return p->rchild;                                // rchild 是后继线索
}

// 带头结点的中序线索树，重新遇见头结点就结束
void InOrderTraverse(ThreadTree head) {
    ThreadTree p = FirstNode(head->lchild);          // 从根的最左下开始
    while (p != head) {
        visit(p);
        p = NextNode(p);
    }
}
```

```cpp

```

### 先序线索二叉树的遍历

先序线索树的后继更好算。`ltag == 0` 说明还有左孩子，下一步直接走左孩子，`ltag == 1` 说明没有左孩子，`rchild` 要么指右孩子，要么就是后继线索。

从根 A 出发，每一步只看当前结点的 `ltag`，不用回头。

:::animation thread-traverse
order: preorder
:::

这样走出来的序列是 A，B，D，G，C，E，F。在带头结点的线索树里，最后一个结点 F 的右指针在收口时已经指回头结点，走到它就停。

:::tabs
```c
// 带头结点的先序线索树
void PreOrderTraverse(ThreadTree head) {
    ThreadTree p = head->lchild;                     // 根
    while (p != head) {
        visit(p);
        // 有左孩子就走左孩子，否则 rchild 要么是右孩子，要么是后继线索
        p = (p->ltag == 0) ? p->lchild : p->rchild;
    }
}
```

```cpp

```

### 后序线索二叉树的遍历

后序线索树不带头结点。后序的后继不好找，要知道双亲才能判断下一步往哪走，但是我们可以换一种思路：去找前驱。

`rtag == 0` 时前驱是右孩子，否则前驱是左孩子或者左线索。从根 A 开始反复取前驱，收集到的是倒着的后序序列 A，C，F，E，B，D，G，把它压进栈再弹出来，就是正序的后序 G，D，B，E，F，C，A。

:::animation thread-traverse
order: postorder
:::

动画最后一步会把收集顺序整个反过来，所以屏幕上最后亮出来的序列才是真正的后序。倒序这一步是遍历完之后单独做的，不影响前面找前驱的过程。

:::tabs
```c
// 后序线索树不带头结点。后继要知道双亲，但前驱很好找：
// rtag 为 0 时前驱是右孩子，否则是左孩子或者左线索。
void PostOrderTraverse(ThreadTree root) {
    ThreadTree stack[MAXSIZE];
    int top = 0;
    ThreadTree p = root;                                   // 根是后序的最后一个结点
    while (p) {
        stack[top++] = p;                                  // 先倒着收集
        p = (p->rtag == 0) ? p->rchild : p->lchild;
    }
    while (top > 0) visit(stack[--top]);                   // 弹出就是后序
}
```

```cpp
// 后序线索树不带头结点。后继要知道双亲，但前驱很好找：
// rtag 为 0 时前驱是右孩子，否则是左孩子或者左线索。
void PostOrderTraverse(ThreadTree root) {
    std::vector<ThreadTree> stack;                         // 先倒着收集
    for (ThreadTree p = root; p != nullptr; p = (p->rtag == 0) ? p->rchild : p->lchild) {
        stack.push_back(p);
    }
    for (auto it = stack.rbegin(); it != stack.rend(); ++it) visit(*it);  // 倒出来就是后序
}
```

```java
// 后序线索树不带头结点。后继要知道双亲，但前驱很好找：
// rtag 为 0 时前驱是右孩子，否则是左孩子或者左线索。
static void postOrderTraverse(ThreadNode root) {
    Deque<ThreadNode> stack = new ArrayDeque<>();          // 先倒着收集
    for (ThreadNode p = root; p != null; p = (p.rtag == 0) ? p.rchild : p.lchild) {
        stack.push(p);
    }
    while (!stack.isEmpty()) visit(stack.pop());           // 弹出就是后序
}
```
