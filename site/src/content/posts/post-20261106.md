既然JSON 已经是全网事实上的数据标准了，几乎所有语言都原生支持，为什么我们还要折腾 YAML 和 TOML呢？

JSON 的确统治了 Web，但它的基因是为**“机器与机器之间传输数据”**设计的。一旦你把它当成“人与机器交互的配置文件”，痛点就会接踵而至：

- 想写一段配置说明？抱歉，JSON 原生不支持注释
- 复制粘贴多打了一个逗号？直接语法报错
- 嵌套层级一深，满屏的花括号和引号直接让可读性断崖式下跌

这就是为什么在现代开发技术栈中，YAML 和 TOML 成了程序员无法绕过的“两座大山”。我们不能只是停留在数据通讯的舒适区，掌握 YAML 和 TOML ，我们才能看到现代工程化和云原生的全貌。

## YAML

 ### 什么是 YAML
YAML 目前的官方全称为*“YAML Ain't Markup Language（YAML 不是标记语言）”*，但有意思的是，其实 YAML 一开始的意思是 *“Yet Another Markup Language（还是一种标记语言）”*。这是因为当时的设计者意识到 YAML 的核心目的并不是像 HTML 那样标记文档内容，而是表达和序列化数据。官方页面在 [yaml.org](https://yaml.org/)。

也就是说：**YAML 的重点不是给文本添加标记，而是描述数据本身。**

YAML 的核心特点如下：

- 可读性强：语法简洁，接近自然书写，减少了大量括号和引号。
- 缩进表示层级：通过空格缩进表示对象之间的嵌套关系，层次清晰。
- 支持多种数据类型：包括字符串、数字、布尔值、空值、对象和数组等。
- 支持数据嵌套：可以通过对象和数组的组合表达复杂的数据结构。
- 支持注释：使用 `#` 添加注释，方便开发人员理解和维护。
- 跨语言兼容：Java、Python、C++、Go 等主流语言均有对应的解析工具。
- 适合配置管理：广泛应用于 Docker Compose、Kubernetes、GitHub Actions 等工具。
- 语法对缩进敏感：缩进错误可能导致解析失败，部分隐式类型规则也容易产生歧义。

> [!IMPORTANT]
> YAML 文件有两种扩展名：`.yaml`（官方推荐），和.`yml`（更加常见），二者等效。

### YAML 的语法规则

总而言之，YAML 的语法遵循以下的5个总原则：

- 缩进表示层级：通过空格缩进表示数据的嵌套关系，不能使用 `Tab` 制表符，且同一层级的缩进必须保持一致
- 键值对使用冒号分隔：使用 `key: value` 表示键值对，冒号后面必须有空格
- 数组使用 - 表示：使用短横线加空格 -  表示数组中的一个元素，每个元素通常独占一行
- 支持对象与数组嵌套：可以通过缩进组合键值对和数组，构建复杂的层级数据结构
- 合理使用引号和注释：字符串通常可以省略引号，但遇到特殊字符或容易产生类型歧义的内容时应使用引号，用 `#` 添加注释

#### 数据类型

YAML 的常用类型靠写法区分，同一个值写成不同的样子就是不同的类型。

**1. 字符串**

```yaml
plain: hello world
single: 'C:\Users\puresky'
double: "第一行\n第二行"
```

不加引号也能写字符串，你大可以遇到容易被误读的字符再补引号。注意单引号里的反斜杠不转义，双引号里 `\n` 这类转义才会生效。

**2. 整数**

```yaml
count: 42
offset: -7
mask: 0x1F      # 十六进制，等于 31
```

整数直接写十进制就行，也支持 0x 开头的十六进制。

**3. 浮点数**

```yaml
rate: 3.14
distance: 1.5e+8   # 科学计数法，指数建议带上符号
upper: .inf       # 正无穷
invalid: .nan
```

浮点数可以带小数点或者指数，`.inf` 和 `.nan` 分别表示无穷大和 NaN。

**4. 布尔值**

```yaml
enabled: true
disabled: false
```

布尔值写成 true 和 false，不加引号，建议全小写。

**5. 空值**

```yaml
nickname: null
alias: ~
remark:
```

`null` 和 `~` 都表示空值，键后面什么都不写也算空值，解析后对应 Python 里的 None 或者 JavaScript 里的 null。

**6. 日期和时间**

```yaml
date: 2026-11-06
time: 2026-11-06T15:17:19+08:00
```

符合 ISO 8601 的写法很多解析器会直接读成日期对象，想让它保持字符串就加引号。

**7. 数组与对象**

```yaml
person:
  name: puresky
  age: 20
skills:
  - Java
  - Python
```

对象是一组键值对，数组是若干以 `-` 开头的元素，两者可以互相嵌套。

#### 类型转换

YAML 没有把值从一个类型强制转成另一个类型的语法，类型在解析时由写法决定，想改变类型只有两条路：**改写法或者加标签。**

**1. 加引号就是字符串**

```yaml
version: 1.10   # 浮点数，读出来是 1.1
port: "8080"    # 字符串，不会被当成数字
```

任何值加上引号都会变成字符串，版本号和编号这类不参与运算的值最好加引号。

**2. 用标签指定类型**

```yaml
code: !!str 42         # 字符串 "42"
count: !!int "42"      # 整数 42
price: !!float "3.14"  # 浮点数 3.14
flag: !!bool "true"    # 布尔 true
```

标签写在值前面可以直接声明类型，优先级高于自动推断，适合把类型钉死。

**3. 隐式类型由解析器决定**

```yaml
value: on
```

> [!NOTE]
> 同一个 `on`，YAML 1.1 的解析器（比如 PyYAML）读成布尔 true，YAML 1.2 的解析器（比如 js-yaml）读成字符串 “on”。


**4. 空字符串不是空值**

```yaml
empty_string: ""
empty_value:
```

第一行是长度为零的字符串，第二行是空值，两者在大多数语言里对应完全不同的东西。

### 特殊语法

**1. 注释**

```yaml
# 整行注释
name: puresky  # 行尾注释
```

井号出现在行首或者空白之后才算注释，紧跟在字符后面的井号只是普通字符。

**2. 块字符串**

```yaml
literal: |
  第一行
  第二行
folded: >
  这是一段
  很长的话
```

竖线保留换行，大于号把换行折成空格，在符号后面加一个减号（`|-`）能去掉末尾的换行。

**3. 锚点与合并**

```yaml
defaults: &base
  timeout: 30
  retries: 3

service:
  <<: *base
  timeout: 60
```

`&` 定义锚点，`*` 引用锚点，`<<` 把引用对象里的字段合并进来，同名字段以当前节点为准。合并键是 YAML 1.1 的扩展，主流解析器都支持。

**4. 多文档**

```yaml
---
kind: Deployment
---
kind: Service
...
```

一个文件可以放多份独立的文档，`---` 开始一份新文档，`...` 表示结束（可以省略）。

**5. 行内写法**

```yaml
ports: [80, 443]
person: {name: puresky, age: 20}
```

方括号和花括号可以在一行里写数组和对象，和缩进写法等价，适合短小的数据。

#### 常见错误

**1. Tab 缩进**

```yaml
# 下面这一行开头的缩进是 Tab，解析会直接报错
services:
	web: nginx
```

YAML 只允许用空格缩进，混进 Tab 就会解析失败，编辑器里记得把 Tab 设成空格。

**2. 冒号后面少空格**

```yaml
# 错误：整行被当成一个普通字符串
name:puresky
```

冒号后面必须有一个空格，写成 `name: puresky` 才是一个键值对。

**3. 短横线后面少空格**

```yaml
# 错误：-Java 被当成一个普通字符串
skills:
  -Java
```

数组元素的短横线后面必须跟空格，写成 `- Java` 才是一行数组元素。

**4. 中文标点混进语法**

```yaml
# 错误：这里用的是全角冒号
name： puresky
```

YAML 的分隔符只能是半角冒号，从中文输入法切过来时最容易带出全角标点。

**5. 特殊字符没加引号**

```yaml
# 错误：值里的冒号被当成新的键值对
message: 时间: 12:30

# 错误：井号开头的值被当成注释，值是 null
color: #ff0000
```

值里出现冒号加空格或者以井号开头时都要加引号，写成 `message: "时间: 12:30"` 和 `color: "#ff0000"` 才对。

**6. 重复的键**

```yaml
port: 8080
port: 9090
```

很多解析器遇到同名键不会报错，直接用后一个值，排查问题时很难发现。

**7. 块字符串缩进不够**

```yaml
# 错误：内容没有比键缩进得更深
command: |
npm install
```

竖线后面的内容必须比键缩进更深，缩进不够会直接解析失败。

#### 综合示例：一个 Skill 的 SKILL.md

我们在这里就不再过多赘述 Skill 是什么了，一个技能就是一个目录，核心就是根目录下的 那个 SKILL.md。这个文件分两半，开头和结尾各用一行 `---` 夹一段 YAML 写元数据，后面接 Markdown 正文写步骤：

```text
.agents/skills/site-release/
├── SKILL.md
├── references/
│   └── rollback.md
└── scripts/
    └── check-dist.mjs
```

开头这段 YAML 大概长这样：

```yaml
---
# 技能的标识，加载器按这个名字索引
name: site-release
# 什么时候用它，写在 description 里
description: >-
  把站点的构建产物发布到 Cloudflare Workers。
  用户要求部署或者上线站点时使用。
license: MIT
version: "1.4"          # 加引号，避免被解析成浮点数
enabled: true
allowed-tools: [Read, Write, Bash]
max_turns: 12
timeout: null           # 不限制执行时长
metadata:
  author: puresky
  updated: 2026-11-06   # 会被解析成日期
  defaults: &defaults
    retries: 1
    confirm: true
  jobs:
    preview:
      <<: *defaults
      target: staging
    production:
      <<: *defaults
      target: production
      confirm: false
---
```

可以看到这一小段把前面的语法点基本都用上了：`>-` 折叠多行描述，`"1.4"` 用引号保住字符串，`[Read, Write, Bash]` 是行内数组，`&defaults` 配 `<<` 复用公共字段，`updated` 是日期，`timeout: null` 是空值。

> [!NOTE]
> 很多真实的 Skill 文件只写 `name` 和 `description` 两个字段，这里多出来的字段只是为了把语法点演示全，把你的 Skill 搞的太臃肿绝对不是一个好事。 description 是模型决定要不要加载这个技能的唯一依据，所以它非常重要，写含糊了技能就等于不存在。


开头那行 `---` 同时也是 YAML 的文档开始标记，结尾那行只是 frontmatter 的边界，Markdown 工具会把它中间的部分单独切出来交给 YAML 解析器。

正文那一半就是普通的 Markdown，加载器最后读到的就是它，例如：

```markdown
# 发布站点

1. 跑 `npm run check`，有报错先修。
2. 跑 `npm run build`，确认 dist 体积没有异常。
3. 跑 `npm run deploy`，把 dist 传到 Cloudflare。
4. 打开正式域名复验页面。

需要回滚时读 `references/rollback.md`。
```

- [格式转换](https://www.json2yaml.com/)

## TOML

### 什么是TOML

你在先前已经看到，TOML 的全程是：

*Tom's Obvious, Minimal Language*（Tom 的显而易见的最简语言）

这是因为 TOML 的作者叫做[Tom Preston-Werner](https://tollbit.forbes.com/profile/tom-preston-werner/)，他是GitHub 联合创始人之一，也是 TOML 的最初设计者。TOML 的名字就来自他的名字 Tom。

在 TOML 出现之前，开发人员已经有 JSON，XML 和 YAML 等数据格式可以选择。但是这些格式各有一些不足：

- JSON 不支持注释，手动维护配置文件不够方便。
- XML 的标签比较冗长。
- YAML 虽然可读性好，但缩进和隐式类型转换可能带来解析歧义。
于是，软件开发者开始关注一个问题：

能不能设计一种语法简单，类型明确，结构清晰，而且专门适合配置文件的数据格式？于是乎 TOML 就诞生了。经过多个版本的演进，TOML 已经逐渐形成稳定规范，并通过 Rust 的 `Cargo.toml`，Python 的 `pyproject.toml `等开发工具进入了现代软件工程生态。（官方资料：[TOML规范与历史版本](https://toml.io/en/)）

### TOML 的语法规范

在最初的规范中，设计者明确提出了三个目标：

1. 容易阅读：语义应该直观，不需要复杂的标记
2. 结构明确：能够无歧义地映射为哈希表（Hash Table），也就是常见的键值映射结构
3. 方便解析：能够轻松转换成各种编程语言中的数据结构

于是 TOML 便拥有了以下的核心语法特性：

- 大小写敏感：键名、字符串等区分大小写（如 Name 和 name 是不同键）
- UTF-8 编码：文件必须使用 UTF-8 编码存储
- 注释：使用 # 表示单行注释，无多行注释（注释内容从 # 到行尾）
- 键值对核心：所有数据最终都以键值对的形式存储，支持嵌套结构和多种数据类型

### TOML 的基本语法

**1. 键值对**

```toml
name = "puresky"
port = 8080
```

最基本的单位是键值对，写成 `key = value` 的形式，一行一个，等号左边是键，右边是值。等号右边不能是裸词，必须写成字符串，数字，布尔值或者数组和表这类结构。

**2. 注释**

```toml
# 整行注释
port = 8080  # 行尾注释
```

井号到行尾都会被忽略，TOML 没有块注释，想注释多行就每行写一个井号。

**3. 字符串**

```toml
basic = "hello\nworld"         # 双引号，支持转义
literal = 'C:\Users\puresky'   # 单引号，原样保留
multiline = """
第一行
第二行
"""
multiline_literal = '''
第一行
第二行
'''
```

双引号是基本字符串，`\n` 这类转义会生效，单引号是字面量字符串，写什么就是什么。三引号用来写多行，紧跟在开头定界符后面的那个换行会被去掉。

**4. 整数**

```toml
count = 42
million = 1_000_000   # 下划线只是分隔符
hex = 0xDEADBEEF
```

整数可以用下划线分段方便阅读，也支持 `0x` 开头的十六进制。

**5. 浮点数**

```toml
pi = 3.14
planck = 6.626e-34
```

浮点数可以写成小数或者科学计数法，`1` 是整数，`1.0` 才是浮点数。

**6. 布尔值**

```toml
enabled = true
disabled = false
```

布尔值只有全小写的 true 和 false，不加引号。

**7. 日期时间**

```toml
date = 1979-05-27
time = 07:32:00
datetime = 1979-05-27T07:32:00Z
```

TOML 原生支持日期和时间，结尾的 `Z` 表示 UTC，也可以写成 `+08:00` 这样的时区偏移。

**8. 数组**

```toml
ports = [ 8001, 8002 ]
names = [
  "alice",
  "bob",
]
```

数组用方括号，元素之间用逗号隔开，可以拆成多行，最后一个元素后面留逗号也没问题。

**9. 表**

```toml
[server]
host = "localhost"
port = 8080
```

方括号开头的行是一个表，也就是字典或者对象，它下面的键值对都属于这个表，直到出现下一个表头。

**10. 嵌套表**

```toml
[parent.child]
host = "localhost"
```

点号表示层级，`[parent.child]` 等价于在 parent 表里再放一个 child 表。

**11. 表数组**

```toml
[[servers]]
name = "alpha"

[[servers]]
name = "beta"
```

双括号表示数组，每个 `[[...]]` 生成数组里的一个元素，适合写一组结构相同的对象。

**12. 内联表**

```toml
point = { x = 1, y = 2 }
```

内联表用花括号在一行里写完，适合字段少又不需要再往里追加内容的表。

### 综合示例：一份 Codex 的 config.toml

同样的，前面都是零散的写法，这里拿我本机的 Codex 全局配置 `~/.codex/config.toml`（如果你想找自己的那份的话，Windows 上是 `C:\Users\你的用户名\.codex\config.toml`）看一个完整的例子。下面是删掉无关条目和敏感信息之后的节选，注释是为了讲解补的。

```toml
# 顶层键值对，设置默认模型和运行环境
model = "gpt-6-astra"
# 额外提一句，如果你想手动调整Codex里面的模型的上下文窗口那就是改这个数值
model_context_window = 820000
model_provider = "XXX"
model_reasoning_effort = "xhigh"
sandbox_mode = "danger-full-access"

# 数组：收到通知时执行的命令和参数
notify = [ "C:\\Users\\puresky\\AppData\\Local\\OpenAI\\Codex\\codex-computer-use.exe", "turn-ended" ]

# 表：自定义的模型服务商
[model_providers.XXX]
name = "XXX"
base_url = "https://XXX.top/v1"
env_key = "XXX_API_KEY"
wire_api = "responses"

# 表：功能开关
[features]
js_repl = false

# 嵌套表：一个 MCP 服务，命令用单引号写 Windows 路径就不用转义
[mcp_servers.node_repl]
type = "stdio"
command = 'C:\Users\puresky\AppData\Local\OpenAI\Codex\bin\node_repl.exe'
startup_timeout_sec = 120

# 再嵌一层，给这个 MCP 服务单独设置环境变量
[mcp_servers.node_repl.env]
CODEX_HOME = 'C:\Users\puresky\.codex'
BROWSER_USE_MARKETPLACE_NAME = "openai-bundled"

# 单引号键：整段 Windows 路径不转义，原样当一个键名
[projects.'d:\python\puresky-blog']
trust_level = "trusted"

# 表数组：每个技能一条记录，同一个表头可以重复写
[[skills.config]]
name = "superpowers:brainstorming"
enabled = false

[[skills.config]]
name = "superpowers:writing-plans"
enabled = false

[[skills.config]]
path = 'C:\Users\puresky\.codex\skills\emil-design-eng\SKILL.md'
enabled = false

# 带点号的键要加引号，不然会被拆成多层表
[tui.model_availability_nux]
"gpt-5.6" = 1
```

这份文件把 TOML 的写法基本凑齐了：最上面是顶层键值对，`model_context_window` 是整数，`notify` 是数组，`[model_providers.XXX]` 是表，`[mcp_servers.node_repl.env]` 是嵌套表，`[[skills.config]]` 是表数组，同一个表头可以重复写多次。`[projects.'d:\python\puresky-blog']` 用单引号把一整段 Windows 路径包起来当键名，反斜杠不用转义。这里注意 `"gpt-5.6" = 1` 里的引号不能省，因为键里有点号，不加的话 `gpt-5.6 = 1` 会被当成 `gpt-5` 表里的 `6 = 1`。

Codex 启动时把这份文件读成一个哈希表，再按表各取所需：顶层的 `model` 决定默认模型，`[model_providers.*]` 定义可选的模型服务商，`[mcp_servers.*]` 里的每个表对应一个要拉起的 MCP 服务，`[[skills.config]]` 则给每个技能单独开关。改完保存，下次启动时生效。和 YAML 的隐式类型不同，这里每个值是什么类型一眼就能看出来，`startup_timeout_sec = 120` 不会被读成字符串。

## JSON，YAML 和 TOML 的对比

最后我们来总结一下三种格式：

| 对比项 | JSON | YAML | TOML |
| --- | --- | --- | --- |
| 注释 | 不支持 | `#` | `#` |
| 层级结构 | 花括号和方括号 | 空格缩进 | 靠表头分节 |
| 键值写法 | `"key": value` | `key: value` | `key = value` |
| 字符串 | 只能双引号 | 可裸写，单引号和双引号都行，还有块字符串 | 四种引号写法 |
| 类型 | 只有六种值类型 | 隐式推断，1.1 和 1.2 有差异 | 显式，没有歧义 |
| 空值 | `null` | `null` 或 `~` | 没有，只能省略键 |
| 日期时间 | 没有原生类型 | 原生支持 | 原生支持 |
| 数组 | 方括号 | 短横线或方括号 | 方括号 |
| 对象 | 花括号 | 缩进 | 表头，表数组和内联表 |
| 复用 | 没有 | 锚点和合并键 | 没有 |
| 典型场景 | 接口传输和数据存储 | K8s，CI 和 Docker 这类平台配置 | Cargo，pyproject 和各类工具配置 |

正如 Hacker News 的讨论所揭示的，没有哪个格式是完美的，在实际的项目开发中，我们需要根据具体的需求选出最适合的那个。
