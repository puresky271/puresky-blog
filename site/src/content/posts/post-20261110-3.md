首先，这里有三个问题，出自*《labuladong的算法笔记》*：

1. 你理解的二叉树的前、中、后序的遍历分别是什么，仅仅是三个顺序不同的列表吗？
2. 请分析后序遍历有何特殊之处？
3. 请分析为什么多叉树没有中序遍历？

我们在这里先不急着给答案，显然如果你就只是跟着教科书中的概念来理解二叉树遍历的话（~~我的博客不属于这一类~~），这三个问题你大概是答不上来的。

我们在[二叉树（其三）：二叉树的遍历和还原二叉树](https://pureskyblog.dpdns.org/posts/post-20261026/)中曾经说过：

> 从物理结构的角度来看，树是一种基于链表的数据结构，因此其遍历方式是通过指针逐个访问节点。然而树是一种非线性数据结构，这使得遍历树比遍历链表更加复杂

但是在这一节，我们将换一种角度来认识这件事。

## 基本框架和引入

我们先来看看二叉树遍历的基本框架（递归），其实真的就那么几行：

:::tabs
```java
// 基本的二叉树节点
class TreeNode {
    int val;
    TreeNode left;
    TreeNode right;
}

void traverse(TreeNode root) {
    if (root == null) {
        return;
    }

    // 前序位置
    traverse(root.left);
    // 中序位置
    traverse(root.right);
    // 后序位置
}
```

```c
#include <stddef.h>

// 基本的二叉树节点
typedef struct TreeNode {
    int val;
    struct TreeNode *left;
    struct TreeNode *right;
} TreeNode;

void traverse(TreeNode *root) {
    if (root == NULL) {
        return;
    }

    // 前序位置
    traverse(root->left);
    // 中序位置
    traverse(root->right);
    // 后序位置
}
```

```cpp
// 基本的二叉树节点
struct TreeNode {
    int val;
    TreeNode *left;
    TreeNode *right;
};

void traverse(TreeNode* root) {
    if (root == nullptr) {
        return;
    }

    // 前序位置
    traverse(root->left);
    // 中序位置
    traverse(root->right);
    // 后序位置
}
```
:::

> [!IMPORTANT]
> 让我提前剧透一下：**`// 前序位置`，`// 中序位置`，`// 后序位置`这三个注释的位置非常重要。**它们不是可有可无的说明文字，而是整段递归框架里的三个时间坐标。前序位置在刚进入节点时执行，中序位置在左子树完成后执行，后序位置在即将离开节点时执行。本题的中序位置没有代码，不代表这个时刻不存在，更不代表另外两段代码可以随意挪动。

`traverse(root.left)` 返回并不意味着整个遍历结束，它只是说明当前节点的左子树已经处理完。程序随后回到当前栈帧，继续执行下一行，也就是遍历右子树。

单链表和数组的遍历都是可以迭代的，也是可以递归的，对于**二叉树，它其实无非就是二叉链表**，由于我们没有办法简单的把二叉树的遍历改写为迭代的形式，那也就自然不存在什么好用的“框架”了，所以我们一般说“二叉树的遍历框架”，那指的基本是递归，本文中的算法实现也将以递归为主。

我问你，那个可爱的 `traverse` 函数到底在做什么？其实人家就只是一个可以遍历二叉树所有节点的函数，**和遍历数组或者链表本质上没有区别**。

从递归结构看，一棵树可以拆成当前节点和它的左右子树，一条链表也可以拆成当前节点和它后面的剩余链表。数组虽然没有指针字段，也能用下标划出“当前元素”和“剩余部分”。所以这三种遍历可以共享同一条思路：**处理当前部分，再把剩余部分交给下一次调用。**

我们干脆也就把这一类递归框架都给出来。为了把四种写法放在同一个代码块里，下面用函数名区分迭代和递归，核心结构不变：

:::tabs
```java
// 迭代遍历数组
void traverseArray(int[] arr) {
    for (int i = 0; i < arr.length; i++) {
        // 访问 arr[i]
    }
}

// 递归遍历数组
void traverseArrayRecursive(int[] arr, int i) {
    if (i == arr.length) {
        return;
    }

    // 前序位置
    traverseArrayRecursive(arr, i + 1);
    // 后序位置
}

// 迭代遍历单链表
void traverseList(ListNode head) {
    for (ListNode p = head; p != null; p = p.next) {
        // 访问 p.val
    }
}

// 递归遍历单链表
void traverseListRecursive(ListNode head) {
    if (head == null) {
        return;
    }

    // 前序位置
    traverseListRecursive(head.next);
    // 后序位置
}
```

:::

数组靠下标 `i` 指向当前元素，链表靠 `head` 指向当前节点。每递归一次，问题就缩小为“剩下的部分”，直到数组越界或链表为空。迭代用循环变量保存这个位置，递归则用每次调用的参数保存它。

只要是以递归的形式完成了一次遍历，那就都可以有**前序位置**和**后序位置**这两个概念：

- **前序位置**：刚进入一个节点（元素）的时候。此时后面的递归调用还没有开始，适合先处理当前节点
- **后序位置**：即将离开一个节点（元素）的时候。此时后面的部分已经处理完，适合收集结果或反向处理当前节点

所以前序和后序指的不是代码写在哪个视觉位置，而是它相对于递归调用的**执行时刻**。把打印语句放在递归调用之前，会从头到尾输出。把它放在递归调用之后，输出顺序就会反过来。

**这也就决定了它们各自的代码执行的时机**，例如这里有一道很简单的题目：我们需要**倒序打印**一条单链表上所有节点的值

以 `1 -> 2 -> 3 -> null` 为例，我们的目标输出是 `3 2 1`，而且不需要修改链表本身。

那怎么办呢，快慢指针？神经病，那没必要也用不了。那就按传统的法子两次遍历先来到尾节点再一路打印回去？那当然是ok的，但是如果你对递归的理解足够透彻，这道题是可以采用**后序遍历**的思想来操作的：

:::tabs
```java
void traverse(ListNode head) {
    if (head == null) {
        return;
    }

    traverse(head.next);
    System.out.print(head.val + " ");
}
```

```c
#include <stdio.h>

void traverse(ListNode *head) {
    if (head == NULL) {
        return;
    }

    traverse(head->next);
    printf("%d ", head->val);
}
```

```cpp
#include <iostream>

void traverse(ListNode* head) {
    if (head == nullptr) {
        return;
    }

    traverse(head->next);
    std::cout << head->val << ' ';
}
```
:::

这段代码只有两行核心语句，但顺序不能交换。每个调用都先把自己的打印操作暂时挂起，等下一层返回后再执行。

图中把过程拆成了“递推”和“回溯”两个阶段：

1. `traverse(1)` 调用 `traverse(2)`，自己的 `print(1)` 留在栈帧里等待执行
2. `traverse(2)` 调用 `traverse(3)`，`traverse(3)` 再调用 `traverse(null)`，打印操作继续逐层等待
3. `traverse(null)` 命中递归出口并返回，不再产生新的调用
4. 程序回到 `traverse(3)`，依次打印 `3`，`2`，`1`，调用栈也随之逐层弹出

换句话说，**递归并没有让指针在链表上反向移动。它只是利用调用栈记住每一层还没执行的打印操作，再按照后进先出的顺序完成它们。**

每个节点都只进入和退出一次，所以时间复杂度是 $O(n)$。调用栈最深为 $n + 1$ 层，其中包含最后的空节点调用，因此额外空间复杂度是 $O(n)$。整个过程只读取节点，不会修改任何 `next` 指针。

所以，我们真的不能就只是把二叉树的三种遍历当成三种顺序不同的`List<Integer>`列表而已，实际上，**我们可以将前、中、后序遍历看为遍历二叉树过程中处理每一个节点的三个特殊时间点**。

> [!IMPORTANT]
> 上面这句话更具体的解释是：**前序位置**的代码在**刚刚进入一个二叉树节点的时候**执行；**后序位置**的代码在**将要离开一个二叉树节点的时候**执行；**中序位置**的代码在一个二叉树节点**左子树都遍历完，即将遍历右子树的时候**执行。

请你记住上面的这段话。

ok现在让我们总结一下，为这一章收一个尾：**二叉树的所有问题就是让你在前、中、后序的位置里面注入巧妙的代码逻辑从而去达到自己的目的。我们只需要单独思考每一个节点应该要干嘛，其他的统统不要管，将它们抛给二叉树遍历框架，递归本身会帮我们在所有的节点上做相同的操作。**

这很难吗，就这么几行代码，本质上一个计数器：

```java
//记录最大深度

//记录遍历到的节点的深度
```

那么现在我们要做的就是在合适的位置安插进这段逻辑，嗯，让我们按最基本的逻辑想一想：

- **我要进入一个节点了**：刚进入一个非空节点，当前路径就多了一个节点，所以 `depth++` 必须放在**前序位置**
- **我要离开一个节点了**：当左右子树都遍历完，即将离开当前节点时，当前路径也要删掉这个节点，所以 `depth--` 必须放在**后序位置**

> [!NOTE]
> 除此之外还有两个时刻要看清楚。当左子树已经遍历完，右子树还没有开始时，程序来到**中序位置**。这道题不需要在这里额外处理什么，但这个时刻依然存在。当**递归来到空节点时**，刚刚走完的是一条完整路径，此时 `depth` 就是这条路径的节点数，可以**拿它更新最大深度**。

这里的 `res` 就是上面说的 `max`。`depth` 和 `res` 都是 `Solution` 的成员变量，所有递归调用共用它们。尤其是 `depth`，**既然进入节点时加了，离开节点时就必须减**，否则从左边回到父节点再进入右边时深度就会越算越大。

### 实现

把计数逻辑放进框架，我们就得到了完整的解法：

:::tabs
```java
class Solution {
    public int res, depth = 0;

    public int maxDepth(TreeNode root) {
        traverse(root);
        return res;
    }

    void traverse(TreeNode root) {
        if (root == null) {
            res = Math.max(res, depth);
            return;
        }

        // 前序位置
        depth++;
        traverse(root.left);
        // 中序位置
        traverse(root.right);
        // 后序位置
        depth--;
    }
}
```

```c
#include <stddef.h>

typedef struct {
    int res;
    int depth;
} Solution;

void traverse(TreeNode *root, Solution *solution) {
    if (root == NULL) {
        if (solution->depth > solution->res) {
            solution->res = solution->depth;
        }
        return;
    }

    // 前序位置
    solution->depth++;
    traverse(root->left, solution);
    // 中序位置
    traverse(root->right, solution);
    // 后序位置
    solution->depth--;
}

int maxDepth(TreeNode *root) {
    Solution solution = {0, 0};
    traverse(root, &solution);
    return solution.res;
}
```

```cpp
#include <algorithm>

class Solution {
public:
    int res = 0;
    int depth = 0;

    int maxDepth(TreeNode* root) {
        traverse(root);
        return res;
    }

    void traverse(TreeNode* root) {
        if (root == nullptr) {
            res = std::max(res, depth);
            return;
        }

        // 前序位置
        depth++;
        traverse(root->left);
        // 中序位置
        traverse(root->right);
        // 后序位置
        depth--;
    }
};
```
:::

以题干中给出的那张图中的树为示例，函数调用时机如下：

1. 刚进入 `20`，程序在**前序位置**执行 `depth++`，此时 `depth = 2`，然后递归遍历左孩子 `15`
2. `15` 的左右空调用都把 `res` 更新为 `3`。离开 `15` 时在**后序位置**执行 `depth--`，于是 `depth` 恢复为 `2`
3. 程序回到 `20` 的**中序位置**。此时左子树已经完成，右子树还没有开始，`20` 自己也还没有离开
4. 接着进入右孩子 `7`，`depth` 再次变成 `3`。等 `7` 完成后，程序才来到 `20` 的**后序位置**，把 `depth` 减回 `1`

整棵树遍历结束后，根节点也会执行自己的 `depth--`，因此 `depth` 回到 `0`，`res` 则保存遍历过程中出现过的最大值 `3`。每个节点只被访问一次，时间复杂度是 $O(n)$。递归调用栈的最大深度为树高 $h$，额外空间复杂度是 $O(h)$，而 `depth` 和 `res` 本身只占 $O(1)$ 空间。

```java
    public int res, rank = 0;

    public int kthSmallest(TreeNode root, int k) {
        traverse(root, k);
        return res;
    }

    public void traverse(TreeNode root, int k) {
        if (root == null) {
            return;
        }

        // 前序位置
        traverse(root.left, k);
        // 中序位置
        rank++;
        if (rank == k) {
            res = root.val;
            return;

        traverse(root.right, k);
        // 后序位置
    }
}
```

提示：

### 审题

给定一个二叉树的根节点 `root`，返回任意路径上节点值之和的最大值。路径至少包含一个节点，不需要经过根节点，但同一节点在一条路径中不能重复出现。

例如 `root = [1,2,3]` 时，最大路径和是 `2 + 1 + 3 = 6`。对于 `root = [-10,9,20,null,null,15,7]`，最大路径和是 `15 + 20 + 7 = 42`。

我说我一开始没思路，但是我知道**我要做的第一件事还是把遍历框架抄一遍**。

只是这次 `traverse` 需要返回一个 `int`，因为父节点要用到左右子树的计算结果。我们先保留 `left` 和 `right` 两个返回值，再暂时用 `0` 占位：

```java
public int traverse(TreeNode root) {
    if (root == null) {
        return 0;
    }

    // 前序位置
    int left = traverse(root.left);
    // 中序位置
    int right = traverse(root.right);
    // 后序位置
    return 0;
}
```

这道题还是可以用一个外部变量 `res` 记录答案，不过和前两题不同，`traverse` 必须有返回值。我们需要知道左右子树分别能给当前节点提供多大的贡献，所以核心逻辑应该放在**后序位置**，等左右两次递归都返回后再计算。

这里要分清两个看起来很像的计算：

- **更新答案时**，当前节点可以作为路径的转折点，把左右两边同时接起来，所以用 `root.val + left + right` 更新 `res`
- **返回父节点时**，路径只能选择左右其中一边继续向上延伸，所以返回 `root.val + max(left, right)`，不能同时带上左右两边

如果某棵子树提供的贡献是负数，直接不要它即可，因此左右贡献都要和 `0` 取最大值。空节点返回 `0`，表示它不提供任何贡献。`res` 必须初始化为整数最小值，而不是 `0`，否则所有节点值都是负数时会得到错误答案。

### 实现

:::tabs
```java
class Solution {
    public int res = Integer.MIN_VALUE;

    public int maxPathSum(TreeNode root) {
        traverse(root);
        return res;
    }

    public int traverse(TreeNode root) {
        if (root == null) {
            return 0;
        }

        // 前序位置
        int left = Math.max(traverse(root.left), 0);
        // 中序位置
        int right = Math.max(traverse(root.right), 0);
        // 后序位置
        res = Math.max(res, root.val + left + right);
        return root.val + Math.max(left, right);
    }
}
```

```c
#include <limits.h>
#include <stddef.h>

typedef struct {
    int res;
} Solution;

int traverse(TreeNode *root, Solution *solution) {
    if (root == NULL) {
        return 0;
    }

    // 前序位置
    int left = traverse(root->left, solution);
    if (left < 0) {
        left = 0;
    }
    // 中序位置
    int right = traverse(root->right, solution);
    if (right < 0) {
        right = 0;
    }
    // 后序位置
    int pathSum = root->val + left + right;
    if (pathSum > solution->res) {
        solution->res = pathSum;
    }
    return root->val + (left > right ? left : right);
}

int maxPathSum(TreeNode *root) {
    Solution solution = {INT_MIN};
    traverse(root, &solution);
    return solution.res;
}
```

每个节点只被访问一次，时间复杂度是 $O(n)$。递归调用栈的最大深度为树高 $h$，额外空间复杂度是 $O(h)$。
