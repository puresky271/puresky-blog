首先，我们还是先来回顾一下虚拟头节点的原理和用法。

## 头节点为什么特殊

对于普通的单链表结构而言，`head` 是一个引用，它保存第一个真实节点的地址，但 `head`本身并不是节点，真正存数据的节点从它指的位置开始，每个节点用一个 `next` 域串起后一个节点，最后一个节点的 `next` 是 `null`。

删除其他位置的节点很统一：找到待删节点的前驱 `prev`，让它跳过待删节点 `curr`，执行 `prev.next = curr.next` 就行。也就是说对于删一个普通节点，我们改的是前驱节点的 `next` 域，被删的那个节点自己甚至不用参与操作。

可是头节点没有前驱。`head` 指向第一个真实节点，这个节点前面什么都没有，那也自然没有“前驱的 `next`”可以改。有人可能想照葫芦画瓢，写 `head.prev.next = head.next`。可惜单链表节点里根本没有 `prev` 这个域，这行代码连编译都过不去。

所以删除头节点只能换个写法，**直接让 `head` 指向第二个节点**，也就是 `head = head.next`。但我们会发现：**两种删除看上去都是“删掉一个节点”，但是一套动的是引用变量 `head`，一套动的是某个节点的 `next` 域。**

这就是普通链表最别扭的边界：要删的节点恰好是第一个时，代码得先判断一次“它是不是头节点”，再走另一条分支。判断一次本身不算什么，麻烦的是这种特判会渗透到很多地方。删除，插入，合并，凡是从头开始动结构的操作都要额外照顾第一个节点，这很不好，我们不希望这样。

写成代码就是下面这两行，赋值的目标完全不同：

```java
// 删除头节点：改的是 head 这个引用
head = head.next;

// 删除中间的节点：改的是前驱节点的 next 域
prev.next = curr.next;
```

当然代码本身都不复杂，难的是写题的人得一直记着“我现在删的是不是第一个”，一旦记漏就会在某个不起眼的用例上出错。

### 补一个永远存在的前驱

既然问题的根子是头节点没有前驱，那就人为给它造一个。我们在真正的第一个节点前面挂一个节点，它不存业务数据，只负责当那个永远存在的前驱（这种节点有的资料也叫哨兵节点）。`dummy` 指向这个虚拟节点，虚拟节点的 `next` 指向原来的 `head`。

`dummy` 是指向虚拟节点没错，但 `head` 可是仍指向第一个真实节点，虚拟节点里的 `-1` 只是个占位，没有任何业务含义。更重要的是，虚拟头节点没有改变真实节点之间的连接关系。`10 → 20 → 30` 还是 `10 → 20 → 30`，只是在最前面多了一个入口，原来 `head` 指向哪里，现在还是哪里。

把虚拟节点挂上去之后，第一个真实节点的处境就完全变了：

第一个真实节点现在有前驱了，这个前驱就是虚拟头节点。于是删除它只需要执行 `dummy.next = dummy.next.next`，改的是虚拟节点的 `next` 域，和删除中间节点时改前驱的 `next` 域是同一个动作。这么一来，原本要单独写一条分支的情况现在就并入了普通删除。

```java
ListNode dummy = new ListNode(-1);   // 虚拟头节点，值只是占位
dummy.next = head;                   // 把原来的链表挂在它后面

dummy.next = dummy.next.next;        // 删除第一个真实节点，和删除普通节点是同一个操作

return dummy.next;                   // 返回真实的链表入口，不是 dummy
```

### 工作指针到底该从哪里起步

`dummy` 只是一个挂在那里的入口，真正干活的是从它出发的指针变量。围绕 `dummy` 起步的写法有两种。

第一种是 `ListNode p = dummy`。`p` 和 `dummy` 一开始指向同一个节点，**但 `p` 的用途是往下走，修改链表结构，`dummy` 则从头到尾不动，最后靠它取回真实链表的入口**。

第二种是 `ListNode first = dummy.next`，它把第一个真实节点保存下来，记住操作开始时的入口。这个入口是会过期的：链表结构一变，`first` 里存的引用就可能不再指向新链表的头，所以最后依旧要从 `dummy.next` 现取，而不是拿 `first` 顶上去。

> [!TIP]
> 不少题解把方法参数直接命名为 `head`，这时候方法体里就不能再写 `ListNode head = dummy.next;`，因为参数变量已经占用了 `head` 这个名字，重复声明编译不过。所以保存入口的变量一般叫 `first`，或者干脆不保存，最后直接 `return dummy.next;`。


让我们用一个最典型的场景来感受工作指针怎么走：删除链表里所有值为 2 的节点。

假设链表是 `dummy → 1 → 2 → 3 → 2 → 4 → null`，`p` 一开始和 `dummy` 指向同一个虚拟节点。

那为什么不让 `p` 直接从第一个真实节点开始呢？因为循环里真正动手的地方是 `p.next`。我们说过，要把一个节点从链表里摘掉，得改它前驱的 `next` 域，所以 `p` 必须停在待删节点的前一个位置。让 `p` 从 `dummy` 出发，虚拟节点也就成了一个能改 `next` 域的对象，第一个真实节点被删时同样不用特判。

```java
class Solution {
    public ListNode removeElements(ListNode head, int val) {
        ListNode dummy = new ListNode(-1);
        dummy.next = head;
        ListNode p = dummy;                  // 工作指针从虚拟头节点起步

        while (p.next != null) {
            if (p.next.val == val) {
                p.next = p.next.next;        // 跳过待删节点，p 原地不动，继续检查接上来的节点
            } else {
                p = p.next;                  // p 前进一格，去看下一个节点
            }
        }

        return dummy.next;
    }
}
```

两个 2 都删完之后，链表变成 `1 → 3 → 4`，`dummy.next` 恰好就是结果的头。

注意循环里那两处操作只差赋值目标：一个写变量 `p`，一个写节点 `p` 的 `next` 域，这两行代码的逻辑查理十万八千里，我们接下来来具体的说一下：

### 区分移动指针和改链表

`p = p.next` 和 `p.next = p.next.next` 非常容易搞混。前者把 `p` 这个变量里的引用换成下一个节点，工作指针往前挪一格，链表本身的连接关系一点都没动。而后者取出 `p.next` 和 `p.next.next` 两个引用，把后者的值写进节点 `p` 的 `next` 域，被跳过的那个节点就从链条里消失了——**一个是给变量赋值，一个是给对象的字段赋值**。

如果你想让工作指针移到下一个节点，但手一滑写成 `p.next = p.next.next`，那节点就被删掉了。想跳过待删节点，又顺手写成 `p = p.next`，`p` 跑到了待删节点身上，后面再改 `p.next`改的就不是前驱的 `next` 域了，闹麻了。

总而言之这个区分一定要记住，不然会越写越乱。

> [!TIP]
> 另外还有一个坑点：dummy.next` 改指向之后，之前保存的引用不会跟着变。所以链表的操作做完之后，正确的返回值是从 `dummy` 现取，也就是 `return dummy.next;`，而不是返回操作之前保存的 `first` 之类，也不是返回方法参数里的 `head`。

### 怎么用

判断标准其实只有一条：**这个变量是用来改链表的，还是用来指路的？**

| 写法 | 指向 | 常见用途 |
| --- | --- | --- |
| `ListNode p = dummy` | 虚拟头节点 | 改链表结构，找前驱节点，合并链表 |
| `ListNode first = dummy.next` | 第一个真实节点 | 保存真实链表的入口 |
| `ListNode cur = dummy.next` | 第一个真实节点 | 从真实节点开始遍历 |
| `ListNode tail = dummy` | 虚拟头节点 | 从头往后逐个拼接新节点 |

总而言之，你可以把 `dummy` 当成一个永远不动的总入口，它只负责两件事：一开始把真实链表挂到自己身后，最后把真实的入口交出去。`p` 这样的工作指针，还有 `cur` 和 `prev`，负责在执行算法时挪位置和改结构，该往前挪就往前挪，该停在谁前面就停在谁前面，就这样。

## 力扣第206题：反转链表（迭代版）

给你单链表的头节点 head ，请你反转链表，并返回反转后的链表。
 
示例 1：

![image](./images/post-20261114/mwgd823a-image.png)

- 输入：head = [1,2,3,4,5]
- 输出：[5,4,3,2,1]
示例 2：

- 输入：head = [1,2]
- 输出：[2,1]

示例 3：

- 输入：head = []
- 输出：[]
 
提示：

链表中节点的数目范围是 [0, 5000]
`-5000 <= Node.val <= 5000`

### 审题

### 实现

#### 不加dummy

```java
class Solution {
    public ListNode reverseList(ListNode head) {
        ListNode cur = head;
        ListNode pre = null;
        ListNode temp = null;
        while(cur != null){
            temp = cur.next;// 保存下一个节点
            cur.next = pre; // 反转当前节点的指针
            pre = cur;// 移动 prev 和 cur
            cur = temp;
        }     
        // 此时 cur 已经移到最后一个节点的后面了，所以需要返回 pre
        return pre;
    }
}
```

#### 加了dummy

```java
class Solution {
    public ListNode reverseList(ListNode head) {
        // 创建一个虚拟头节点，初始时指向 head
        ListNode dummy = new ListNode(0);
        dummy.next = head;

        ListNode prev = null;
        // 从头节点开始，依次向后移动
        ListNode cur = dummy.next; 

        while (cur != null) {
            ListNode temp = cur.next; // 保存下一个节点
            cur.next = prev; // 反转当前节点的指针
            prev = cur; // 移动 prev 和 cur
            cur = temp;
        }

        dummy.next = prev;
        return dummy.next;
    }
}
```

## 力扣第24题：两两交换链表中的节点

给你一个链表，两两交换其中相邻的节点，并返回交换后链表的头节点。你必须在不修改节点内部的值的情况下完成本题（即，只能进行节点交换）。

- 输出：[2,1,4,3]

示例 2：

- 输入：head = []
- 输出：[]

示例 3：

- 输入：head = [1]
- 输出：[1]

链表中节点的数目在范围 [0, 100] 内
`0 <= Node.val <= 100`

### 实现

class Solution {
public:
    ListNode* swapPairs(ListNode* head) {
        if (head == nullptr || head->next == nullptr) {
            return head;
        }

        // 第一次交换，单独确定新的头节点
        ListNode* first = head;
        ListNode* second = head->next;

        first->next = second->next;
        second->next = first;

        head = second;

        // 从第二组开始，正常交换
        ListNode* p = first;

        while (p->next != nullptr && p->next->next != nullptr) {
            ListNode* first = p->next;
            ListNode* second = first->next;

            first->next = second->next;
            second->next = first;
            p->next = second;

            p = first;
        }

        return head;
    }
};
