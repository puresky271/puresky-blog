## 这个系列要做什么

我在准备东京大学创造情报学专攻（CI）的入试。按最近一版入试案内，CI 修士的冬入试里一般教育科目只考一门编程，形式是一场 150 分钟的实技考试。考试当天自带笔记本电脑，语言任选，可以翻本机存的文档，用本机的库，甚至直接抄自己以前写的源码，但不能联网。最新一版入试案内里还明确写了不许使用 LLM 和 Copilot 这类基础模型。下午有一轮五分钟左右的面试，会围绕上午的题目问几句。

官方公开的编程过去问只有夏入试那几份，从 2022 年度到 2026 年度，一共五套，冬入试的题目没有在官网上公开。好在两边的编程科目考法相同，拿这些夏入试的题练手，就是最接近实战的模拟。这个系列会按年度逐份拆开，写清楚题意，算法和完整实现。

第一篇处理最新的一份，也就是 2026 年度夏入试（2025 年 8 月实施）的编程实技题。题面可以在[官网这里](https://www.i.u-tokyo.ac.jp/edu/course/ci/2026/2025-8-prog.pdf)下载。

有一个必须提前说明的点。考场里发给考生的是一张 USB 盘，里面除了题面还有若干数据文件（data1a.txt 这样的名字），每道小题对应几份数据。这些数据文件不在公开的 PDF 里，官方公开的资料里也没有标准答案。所以这篇文章不复述那几份数据的结果，而是把通用解法完整写出来，再用题面自带的四个示例图做逐格验证。等你有机会拿到真实数据，程序可以直接跑。

## 题目：一张网格画布

题面本身很短。考虑一张由 1×1 正方形格子组成的画布，左上角是第 0 行第 0 列，格子用 (x, y) 表示，x 是列，y 是行。开始时所有格子都是白色，然后用一串数字依次画出长方形，圆和线段，把经过的格子涂成黑色（色号 0）或灰色（色号 1）。同一个格子被涂多次时，最后涂的颜色生效。

五个问题分别问：三种图形各画了几个，覆盖所有非白格子的最小外接矩形右下角在哪，黑色和灰色各有多少格，两种颜色各自最大的连通分量有多大，从外接矩形左上角走到右下角，在“与起点颜色不同的格子最少”的前提下最短要走多少格。

数据文件里只有一串逗号分隔的整数，所以整道题的骨架很清楚：先把画布模拟出来，再在结果上做五次扫描。真正麻烦的是三种图形的落格规则，尤其是圆和线段，因为它们都要求“格子内部”与图形有公共部分，边界不算。

坐标的细节值得多说一句。题目里的 (x, y) 指的是格子，不是格点。格子 (x, y) 的左上顶点是格点 (x, y)，两者同名但含义不同。圆的圆心和线段的端点都落在格点上，判定时要用这个对应关系。

### 长方形

最容易的一种。数列是 `0, c, x1, y1, x2, y2`，满足 x1 < x2 且 y1 < y2。四个角上的格子是 (x1,y1), (x2,y1), (x2,y2), (x1,y2)，把这四个格子围成的矩形内部全部涂成 c，包含四条边。等价于把所有满足 x1 ≤ x ≤ x2 且 y1 ≤ y ≤ y2 的格子都涂上颜色。

```python
def paint_rectangle(canvas, shape):
    """长方形是整个内部都涂，四条边也包含在内。"""
    _, color, x1, y1, x2, y2 = shape
    for y in range(y1, y2 + 1):
        for x in range(x1, x2 + 1):
            canvas[x, y] = color
```

### 圆

数列是 `1, c, x, y, r`，圆心在格点 (x, y)，半径 r，且 1 ≤ r ≤ x，r ≤ y，也就是圆整体落在画布内。要涂的格子是“格子内部”与“圆和圆的内部”有公共部分的那些。两个集合都把边界排除在外，所以判定条件是格点到格子的最小距离**严格小于**半径。

格点到格子的最小距离可以拆成两个方向。格子 (i, j) 的横坐标范围是 (i, i+1)，圆心横坐标是 cx，那么水平方向的距离是

```text
dx = max(i - cx, cx - (i + 1), 0)
```

dy 同理。由于格子是闭方块，最近点一定落在它的边界上，两个方向的距离各自独立，于是最近距离的平方就是 dx² + dy²。判定时只比较整数平方，不做开方，既快又没有浮点误差。

```python
def paint_circle(canvas, shape):
    """圆心是格点，只有到格子闭包的最小距离严格小于半径的格子才涂。"""
    _, color, cx, cy, radius = shape
    radius_sq = radius * radius
    for y in range(max(0, cy - radius), cy + radius):
        dy = max(y - cy, cy - (y + 1), 0)
        for x in range(max(0, cx - radius), cx + radius):
            dx = max(x - cx, cx - (x + 1), 0)
            if dx * dx + dy * dy < radius_sq:
                canvas[x, y] = color
```

举题面的例子，`1, 1, 5, 4, 4` 一共涂了 60 格，按行数是 6, 8, 8, 8, 8, 8, 8, 6。比如 (0,3) 和 (0,4) 这两个格子到圆心的距离正好等于 4，不涂。差一点写成小于等于就会多涂四格。

### 线段

三种图形里最麻烦的是线段。数列是 `2, c, x1, y1, x2, y2`，两端都是格点，且两点不能重合。要涂的格子是“内部被线段穿过”的那些。

这里的“内部”是开方格，不含边界，于是有两个容易踩的坑。

第一个坑是轴对齐的线段。如果 x1 = x2，线段整条落在一条竖直格线上。格子内部不包含格线，所以它和任何格子都没有公共部分，**一个格子也不涂**。水平线段同理。这不是程序 bug，是题面定义直接推出的结论。

第二个坑是线段恰好穿过格点。比如 `2, 0, 1, 5, 7, 1` 连接 (1,5) 和 (7,1)，中途正好经过格点 (4,3)。在 (4,3) 附近，线段只是擦过四个格子的公共角，并没有进入格子 (4,3) 和 (3,2) 的内部，所以这两格不涂。同一列的两侧格子 (3,3) 和 (4,2) 才被穿过。整条线段最终涂出 8 个黑格。

实现上把线段参数化。设起点 A，终点 B，参数 t 从 0 到 1，线段上的点是 A + t(B − A)。对某个格子，横坐标落在 (x, x+1) 给出一个 t 的开区间，纵坐标落在 (y, y+1) 给出另一个开区间，再和 [0, 1] 取交集。两个区间的交集非空，格子就被穿过。

为了不碰浮点，区间的端点写成“分子/分母”，比较两个端点时交叉相乘。坐标都是整数，乘积也还是整数，这样即使在格点处相切也能判得精确。下面的代码把两个维度的区间分别算出来，最后只比较一次下界和上界。

```python
def segment_cells(x1, y1, x2, y2):
    """返回内部与线段有公共部分的格子。线段的两个端点是格点。

    如果 x1 == x2 或 y1 == y2，线段整条落在格线上，而格子内部是不含边界的开集，
    所以它和任何格子都没有公共部分，一个格子也不涂。这是题面定义直接推出的结论。
    """
    if x1 == x2 or y1 == y2:
        return []
    cells = []
    for y in range(min(y1, y2), max(y1, y2)):
        for x in range(min(x1, x2), max(x1, x2)):
            if segment_hits_cell(x1, y1, x2, y2, x, y):
                cells.append((x, y))
    return cells


def segment_hits_cell(x1, y1, x2, y2, x, y):
    """判断线段 (x1,y1)-(x2,y2) 是否穿过格子 (x, y) 的内部。

    把“x 落在 (x, x+1)”和“y 落在 (y, y+1)”分别解成参数 t 的开区间，
    两个区间与 [0, 1] 的交集非空，就说明线段有一段在格子内部。
    区间端点写成 (分子, 分母)，比较时交叉相乘，全程整数，没有浮点误差。
    """
    low, high = (0, 1), (1, 1)  # t 区间先限制在 [0, 1] 里
    for start, delta, cell in ((x1, x2 - x1, x), (y1, y2 - y1, y)):
        if delta > 0:
            a, b, denominator = cell - start, cell + 1 - start, delta
        else:
            a, b, denominator = start - cell - 1, start - cell, -delta
        low = max_fraction(low, (a, denominator))
        high = min_fraction(high, (b, denominator))
        if not fraction_less(low, high):
            return False
    return True


def fraction_less(left, right):
    return left[0] * right[1] < right[0] * left[1]


def max_fraction(left, right):
    return right if fraction_less(left, right) else left


def min_fraction(left, right):
    return left if fraction_less(left, right) else right
```

这四个结果都和原题印刷的图对得上。为了不只靠眼睛，我把 PDF 第 4 页和第 5 页渲染成 400dpi 的位图，用灰度投影自动定位网格线，再取每个格子中间 70% 的区域，按 3×3 子块的深色像素比例分类：白格几乎没有深色像素，网点灰格有稳定的深色像素比例，黑格几乎整格都是深色，用图 1(a) 已知的 24 个灰格标定阈值之后，白格和灰格分得很开。四张图一共 264 个格子逐格比对，和程序输出零格不一致，没有不可靠格，也没有人工硬判。图 1(b) 的网格是 9 列 8 行，一共 72 个格子，同样全部对上。

后来又把检查扩到 1014 条用例：官方四个示例，十种边界情况，再加上一千条随机数列。这些用例逐条和一份独立写的实现比对，全部通过。随机用例里特意混进了大坐标，圆和格子角点相切，线段经过格点，以及一格都没涂的退化输入。

这一步很值。渲染器是整道题的地基，只要差一格，后面的外接矩形，计数和连通分量都会跟着错，而这类错误在只看最终答案时很难发现。

## 五个问题

画布画好之后，五个问题都是常规操作。

### (1) 数图形

解析数列时按类型消耗固定数量的数字：长方形和线段各 6 个，圆 5 个。顺手计数即可。复杂度只看数列长度。

```python
def parse_sequence(text):
    """把逗号分隔的数字串解析成图形列表。数字之间可以有空白和换行。"""
    numbers = [int(token) for token in text.replace(",", " ").split()]
    shapes = []
    index = 0
    while index < len(numbers):
        kind = numbers[index]
        if kind not in SHAPE_LENGTH:
            raise ValueError(f"未知图形类型 {kind}（第 {index} 个数字）")
        end = index + SHAPE_LENGTH[kind]
        if end > len(numbers):
            raise ValueError("数字不够组成一个完整的图形")
        shapes.append(tuple(numbers[index:end]))
        index = end
    return shapes
```

### (2) 外接矩形

遍历所有非白格子，取 x 和 y 的最小值和最大值。右下角就是 (max x, max y)。

这里有一个很隐蔽的点：外接矩形的四个角不一定是涂过的格子。题面的叠加示例里，外接矩形是 (1,1) 到 (6,6)，但它的左上角 (1,1) 是白格。原因是最左一列来自灰矩形的 x = 1 这条边，最上一行来自黑线段的 y = 1 这条边，两条边根本没有相交在一个已涂的格子上。

### (5) 最少异色格的最短路径

这一问是整道题的重点。设外接矩形左上角的格子为 a，右下角的格子为 b。要找一个从 a 到 b 的格子路径，相邻两步共享一条边。目标是字典序双目标：先让“与 a 颜色不同的格子数”最少，再让路径长度最短。长度按路径上的格子数算，包含两端。

不能直接用普通 BFS。普通 BFS 只优化长度，它会选一条很短但一路擦过好几个异色格的路，而题面要的是异色格优先。可以把每个格子看成一个点，从 u 走到 v 的代价定义成两项：第一项是 v 是否与 a 异色，0 或 1，第二项固定是 1 步。然后按 (异色数, 长度) 的字典序做最短路。

实现上分成两趟更清楚。

第一趟做 0-1 BFS。同色格之间的边代价 0，异色格的边代价 1，用双端队列维护：代价 0 的邻点压到队头，代价 1 的压到队尾。跑完之后，每个格子都有一个最少的异色数 diff。

第二趟只在“等优边”上再 BFS 一次。边 u → v 是等优的，当且仅当 `diff[v] == diff[u] + w(u, v)`。在这些边上做普通 BFS，得到的长度就是最少异色路径里的最短长度。正确性也简单：任何一条达到最优异色数的路径，它的每个前缀也必须是最优的，否则把前缀换成更优的走法，总异色数还能更小。

```python
def min_color_path(canvas, box):
    """从 bbox 左上角 a 走到右下角 b。

    先最小化“与 a 颜色不同的格子数”，再最小化路径长度（格子数，含两端）。
    返回 (最少的异色格数, 最短路径长度)。
    """
    left, top, right, bottom = box
    start, goal = (left, top), (right, bottom)
    base = canvas.get(start, WHITE)

    # 搜索范围取 bbox 外扩一格。bbox 之外全是白格，最优路径不会跑得比这更远：
    # a 非白时，白格与 a 异色，绕到外面只会更差；a 为白时，外面虽然免费，
    # 但把绕远的行程压回 bbox 边上不会让异色数变多。
    lo_x, lo_y = max(0, left - 1), max(0, top - 1)
    hi_x, hi_y = right + 1, bottom + 1
    inside = (lo_x, lo_y, hi_x, hi_y)

    def neighbors(cell):
        x, y = cell
        for nx, ny in ((x - 1, y), (x + 1, y), (x, y - 1), (x, y + 1)):
            if lo_x <= nx <= hi_x and lo_y <= ny <= hi_y:
                yield nx, ny

    # 第一步：0-1 BFS 求每个格子的最少异色数。走到异色格代价 1，走到同色格代价 0。
    infinite = 10 ** 9
    diff = {start: 0}
    queue = deque([start])
    while queue:
        cell = queue.popleft()
        for next_cell in neighbors(cell):
            weight = 0 if canvas.get(next_cell, WHITE) == base else 1
            candidate = diff[cell] + weight
            if candidate < diff.get(next_cell, infinite):
                diff[next_cell] = candidate
                if weight:
                    queue.append(next_cell)
                else:
                    queue.appendleft(next_cell)

    # 第二步：只在“最优边”上再 BFS 一次，求最少异色路径里的最短长度。
    # 一条边 u -> v 是最优边，当且仅当 diff[v] == diff[u] + 代价(u -> v)。
    length = {start: 1}
    queue = deque([start])
    while queue:
        cell = queue.popleft()
        for next_cell in neighbors(cell):
            weight = 0 if canvas.get(next_cell, WHITE) == base else 1
            if next_cell not in length and diff.get(next_cell, infinite) == diff[cell] + weight:
                length[next_cell] = length[cell] + 1
                queue.append(next_cell)

    return diff[goal], length[goal]
```

#### 搜索范围比想象的麻烦

第二趟的 BFS 要限定一个搜索范围，而这里很容易错。

最直觉的想法是只在外接矩形内部搜。这个想法在 a 是黑格或灰格时是对的。因为外接矩形之外全是白格，白格与 a 异色，绕出去每一步都要付一个异色格，把绕出去的部分换回矩形内部的最短路，异色数和长度都不会变大。

但 a 可能是白格。这时候白格与 a 同色，绕到外接矩形外面是零代价的，最优路径真的会跑出去。题面的叠加示例就是这种情况：a = (1,1) 是白格，b = (6,6) 是灰格。只在外接矩形里搜，答案是 (异色 6，长度 11)，把搜索范围外扩一格，正确答案是 (异色 1，长度 15)，路径从 a 出发先往左，再沿着外接矩形的外圈绕到 b 的下方，最后往上一步回到 b。

所以搜索范围要取外接矩形外扩一格，并且坐标夹在 0 以上，因为画布没有负数坐标。外扩一格已经足够：外接矩形外面全是白格，最短路可以贴着外接矩形走，再远只会更长。

用题面另外两张示例图也能验证这个坑。圆示例只在外接矩形里搜会得到 (12, 15)，外扩后是 (0, 19)。线段示例只在内搜是 (1, 9)，外扩后是 (0, 13)。三张图都能看出差别。

#### 一个更省事的写法

如果不想分两趟，也可以把状态直接做成 `(异色数, 长度)` 二元组，用优先队列做 Dijkstra。两项都是非负且沿路径单调不减，字典序比较满足加法相容，Dijkstra 照样成立。只是代码比 0-1 BFS 加一趟 BFS 稍微绕一点，性能也差一些。

## 完整实现

下面是整份程序，Python 标准库，单文件。输入是数据文件路径，输出五问的答案。加 `--json` 可以输出 JSON，方便自动比对。

跑题面那份叠加数据（也就是四个示例里的最后一条），输出是五行动作数字：

```text
(1) 1 0 1
(2) 6 6
(3) 8 20
(4) 4 19
(5) 15
```

```python
#!/usr/bin/env python3
"""东京大学 情报理工学系研究科 创造情报学专攻 2026 年度夏入试 编程实技题 参考实现。

题面：在一张无限大的 1x1 网格画布上，用数列描述长方形、圆和线段，依次涂色，
然后回答关于结果的五个问题。本文件只依赖 Python 标准库，既可以在考场上用，
也是博客文章《东大创造情报编程真题：网格画布与五个追问》里的完整实现。

用法：
    python solve.py data1a.txt          # 打印第 (1) 到 (5) 问的答案
    python solve.py data1a.txt --json   # 同样的答案，输出 JSON，方便自动比对
"""

import json
import sys
from collections import deque

BLACK = 0  # 色号 0
GRAY = 1   # 色号 1
WHITE = 2  # 未被涂过的格子，题面里是白色

# 每种图形占几个数字：0 长方形 6 个，1 圆 5 个，2 线段 6 个。
SHAPE_LENGTH = {0: 6, 1: 5, 2: 6}


def parse_sequence(text):
    """把逗号分隔的数字串解析成图形列表。数字之间可以有空白和换行。"""
    numbers = [int(token) for token in text.replace(",", " ").split()]
    shapes = []
    index = 0
    while index < len(numbers):
        kind = numbers[index]
        if kind not in SHAPE_LENGTH:
            raise ValueError(f"未知图形类型 {kind}（第 {index} 个数字）")
        end = index + SHAPE_LENGTH[kind]
        if end > len(numbers):
            raise ValueError("数字不够组成一个完整的图形")
        shapes.append(tuple(numbers[index:end]))
        index = end
    return shapes


# ── 三种图形的光栅化 ──────────────────────────────────────────────────────


def paint_shape(canvas, shape):
    """把一个图形涂到画布上。canvas 是 {(x, y): 颜色} 的字典，后涂的颜色覆盖先涂的。"""
    kind = shape[0]
    if kind == 0:
        paint_rectangle(canvas, shape)
    elif kind == 1:
        paint_circle(canvas, shape)
    else:
        paint_segment(canvas, shape)


def paint_rectangle(canvas, shape):
    """长方形是整个内部都涂，四条边也包含在内。"""
    _, color, x1, y1, x2, y2 = shape
    for y in range(y1, y2 + 1):
        for x in range(x1, x2 + 1):
            canvas[x, y] = color


def paint_circle(canvas, shape):
    """圆心是格点，只有到格子闭包的最小距离严格小于半径的格子才涂。"""
    _, color, cx, cy, radius = shape
    radius_sq = radius * radius
    for y in range(max(0, cy - radius), cy + radius):
        dy = max(y - cy, cy - (y + 1), 0)
        for x in range(max(0, cx - radius), cx + radius):
            dx = max(x - cx, cx - (x + 1), 0)
            if dx * dx + dy * dy < radius_sq:
                canvas[x, y] = color


def paint_segment(canvas, shape):
    """线段只涂内部被它穿过的格子。"""
    _, color, x1, y1, x2, y2 = shape
    for cell in segment_cells(x1, y1, x2, y2):
        canvas[cell] = color


def segment_cells(x1, y1, x2, y2):
    """返回内部与线段有公共部分的格子。线段的两个端点是格点。

    如果 x1 == x2 或 y1 == y2，线段整条落在格线上，而格子内部是不含边界的开集，
    所以它和任何格子都没有公共部分，一个格子也不涂。这是题面定义直接推出的结论。
    """
    if x1 == x2 or y1 == y2:
        return []
    cells = []
    for y in range(min(y1, y2), max(y1, y2)):
        for x in range(min(x1, x2), max(x1, x2)):
            if segment_hits_cell(x1, y1, x2, y2, x, y):
                cells.append((x, y))
    return cells


def segment_hits_cell(x1, y1, x2, y2, x, y):
    """判断线段 (x1,y1)-(x2,y2) 是否穿过格子 (x, y) 的内部。

    把「x 落在 (x, x+1)」和「y 落在 (y, y+1)」分别解成参数 t 的开区间，
    两个区间与 [0, 1] 的交集非空，就说明线段有一段在格子内部。
    区间端点写成 (分子, 分母)，比较时交叉相乘，全程整数，没有浮点误差。
    """
    low, high = (0, 1), (1, 1)  # t 区间先限制在 [0, 1] 里
    for start, delta, cell in ((x1, x2 - x1, x), (y1, y2 - y1, y)):
        if delta > 0:
            a, b, denominator = cell - start, cell + 1 - start, delta
        else:
            a, b, denominator = start - cell - 1, start - cell, -delta
        low = max_fraction(low, (a, denominator))
        high = min_fraction(high, (b, denominator))
        if not fraction_less(low, high):
            return False
    return True


def fraction_less(left, right):
    return left[0] * right[1] < right[0] * left[1]


def max_fraction(left, right):
    return right if fraction_less(left, right) else left


def min_fraction(left, right):
    return left if fraction_less(left, right) else right


# ── 画布上的五个问题 ──────────────────────────────────────────────────────


def bounding_box(canvas):
    """所有非白格子的最小外接矩形，返回 (左, 上, 右, 下)，没有格子时返回 None。"""
    if not canvas:
        return None
    xs = [x for x, _ in canvas]
    ys = [y for _, y in canvas]
    return min(xs), min(ys), max(xs), max(ys)


def color_counts(canvas):
    black = sum(1 for color in canvas.values() if color == BLACK)
    return black, len(canvas) - black


def largest_components(canvas):
    """黑色、灰色各自最大的四邻接连通分量的大小。"""
    seen = set()
    best = {BLACK: 0, GRAY: 0}
    for cell, color in canvas.items():
        if cell in seen:
            continue
        size = 0
        stack = [cell]
        seen.add(cell)
        while stack:
            x, y = stack.pop()
            size += 1
            for neighbor in ((x + 1, y), (x - 1, y), (x, y + 1), (x, y - 1)):
                if neighbor not in seen and canvas.get(neighbor) == color:
                    seen.add(neighbor)
                    stack.append(neighbor)
        best[color] = max(best[color], size)
    return best[BLACK], best[GRAY]


def min_color_path(canvas, box):
    """从 bbox 左上角 a 走到右下角 b。

    先最小化「与 a 颜色不同的格子数」，再最小化路径长度（格子数，含两端）。
    返回 (最少的异色格数, 最短路径长度)。
    """
    left, top, right, bottom = box
    start, goal = (left, top), (right, bottom)
    base = canvas.get(start, WHITE)

    # 搜索范围取 bbox 外扩一格。bbox 之外全是白格，最优路径不会跑得比这更远：
    # a 非白时，白格与 a 异色，绕到外面只会更差；a 为白时，外面虽然免费，
    # 但把绕远的行程压回 bbox 边上不会让异色数变多。
    lo_x, lo_y = max(0, left - 1), max(0, top - 1)
    hi_x, hi_y = right + 1, bottom + 1
    inside = (lo_x, lo_y, hi_x, hi_y)

    def neighbors(cell):
        x, y = cell
        for nx, ny in ((x - 1, y), (x + 1, y), (x, y - 1), (x, y + 1)):
            if lo_x <= nx <= hi_x and lo_y <= ny <= hi_y:
                yield nx, ny

    # 第一步：0-1 BFS 求每个格子的最少异色数。走到异色格代价 1，走到同色格代价 0。
    infinite = 10 ** 9
    diff = {start: 0}
    queue = deque([start])
    while queue:
        cell = queue.popleft()
        for next_cell in neighbors(cell):
            weight = 0 if canvas.get(next_cell, WHITE) == base else 1
            candidate = diff[cell] + weight
            if candidate < diff.get(next_cell, infinite):
                diff[next_cell] = candidate
                if weight:
                    queue.append(next_cell)
                else:
                    queue.appendleft(next_cell)

    # 第二步：只在「最优边」上再 BFS 一次，求最少异色路径里的最短长度。
    # 一条边 u -> v 是最优边，当且仅当 diff[v] == diff[u] + 代价(u -> v)。
    length = {start: 1}
    queue = deque([start])
    while queue:
        cell = queue.popleft()
        for next_cell in neighbors(cell):
            weight = 0 if canvas.get(next_cell, WHITE) == base else 1
            if next_cell not in length and diff.get(next_cell, infinite) == diff[cell] + weight:
                length[next_cell] = length[cell] + 1
                queue.append(next_cell)

    return diff[goal], length[goal]


# ── 命令行入口 ────────────────────────────────────────────────────────────


def solve(canvas, shapes):
    counts = {0: 0, 1: 0, 2: 0}
    for shape in shapes:
        counts[shape[0]] += 1
    box = bounding_box(canvas)
    black, gray = color_counts(canvas)
    max_black, max_gray = largest_components(canvas)
    if box is None:
        # 图形可能一个格子都没涂到（比如一整份数据都是轴对齐线段），这时没有 bbox。
        bbox = {"left": -1, "top": -1, "right": -1, "bottom": -1}
        path = {"min_diff": 0, "length": 0}
    else:
        min_diff, path_length = min_color_path(canvas, box)
        bbox = {"left": box[0], "top": box[1], "right": box[2], "bottom": box[3]}
        path = {"min_diff": min_diff, "length": path_length}
    return {
        "counts": {"rectangle": counts[0], "circle": counts[1], "segment": counts[2]},
        "bbox": bbox,
        "colors": {"black": black, "gray": gray},
        "components": {"black": max_black, "gray": max_gray},
        "path": path,
    }


def main(argv):
    if len(argv) < 2:
        print("用法：python solve.py DATA.txt [--json]", file=sys.stderr)
        return 1
    with open(argv[1], encoding="utf-8") as handle:
        text = handle.read()
    canvas = {}
    shapes = parse_sequence(text)
    for shape in shapes:
        paint_shape(canvas, shape)
    answer = solve(canvas, shapes)
    if "--json" in argv[2:]:
        print(json.dumps(answer, ensure_ascii=False, indent=2))
    else:
        # 输出固定五行，每行除了题号全是数字，方便直接抄到答题纸或者拿去做自动比对。
        print(f"(1) {answer['counts']['rectangle']} {answer['counts']['circle']} {answer['counts']['segment']}")
        print(f"(2) {answer['bbox']['right']} {answer['bbox']['bottom']}")
        print(f"(3) {answer['colors']['black']} {answer['colors']['gray']}")
        print(f"(4) {answer['components']['black']} {answer['components']['gray']}")
        print(f"(5) {answer['path']['length']}")
    return 0


if __name__ == "__main__":
    sys.exit(main(sys.argv))
```

## 复杂度

设数列长度为 n，画布上非白格子数为 k，外接矩形外扩后的面积为 A。各步的复杂度如下。

| 步骤 | 复杂度 | 说明 |
| --- | --- | --- |
| 解析数列 | O(n) | 一次线性扫描 |
| 画长方形 | O(矩形面积) | 双重循环直接涂 |
| 画圆 | O(r²) | 只枚举能落格的 2r × 2r 区域 |
| 画线段 | O(宽度 × 高度) | 对每个候选格做常数次整数比较 |
| 外接矩形和颜色计数 | O(k) | 遍历已涂格子 |
| 最大连通分量 | O(k) | 每个格子进出栈一次 |
| 最少异色最短路 | O(A) | 0-1 BFS 一次加等优边 BFS 一次，都是线性的 |

数据规模未知，但按题面示意图的量级，画布不会太大，Python 完全跑得动。实测用 300×300 的画布、2000 个图形压测，渲染约 1.0 秒，五问合计约 0.12 秒，其中最大连通分量最慢，约 86 毫秒。真实数据如果很大，把字典换成二维数组或者 numpy 也能救回来。

## 考场上的几条经验

第一，先把解析器写对。这题的数据是逗号分隔的一长串整数，直接按逗号切分再转整数最省事，注意要能容忍空格和换行。

第二，渲染器写完立刻用题面的四个示例验证。四个示例分别覆盖了三种图形和叠加覆盖，是现成的测试集。考场没有网络，也没有 LLM，自己搭一套快速自测比反复肉眼检查可靠得多。

第三，把五个问题拆成五个独立函数，各自在主函数里打印一行。题库里每份数据考的小题不同，输出格式对不上是常见的丢分点，先对格式再对数值。

第四，几何判定尽量用整数。圆用距离平方，线段用分数比较，这样不会出现浮点误差，也不需要 eps。

第五，注意交卷规则。考试结束前要在自己的电脑上建一个以考号命名的文件夹，把程序和相关文件放进去，再拷到 USB 盘上交。这个步骤不要留到最后五分钟。
